# AI咨询转化飞轮

> 面向医疗咨询主管、咨询总监和一线咨询师的开源 Agent Skill：全量复盘咨询，发现关键断点，把销冠动作沉淀为可训练、可复查的团队能力。

AI咨询转化飞轮 V2.2.1 是所有机构共同安装的公共 Core，不是某家机构的定制包。新用户可以先新建并打开一个本地业务文件夹；向导用不超过 5 轮、一次一问的采访了解角色和团队，确认后在当前文件夹下建立标准工作区，再用一通录音、一段微信或一张截图完成首次真实验证。机构资料、患者材料、团队规则、审核记录和个人成长始终留在用户自己的工作区；更新公共 Core 不覆盖这些数据。

没有当前工作空间也可以直接开始五问。向导在摘要页推荐一个新的机构目录，用户确认后自动创建；宿主完全没有本地文件能力时可先临时分析一条，但不会伪装成已经建立团队工作区。

日常运行会为每个有效案例生成标准复盘，再汇总患者优先队列、员工日报、团队重点和每人唯一训练卡；一线还可以围绕患者当前阶段直接生成跟进话术、朋友圈、患者科普和私信承接内容。没有预约、到院和付款结果时，只验证行为改善和管理提效，不宣称转化提升。

支持 WorkBuddy、Trae、Codex、Claude 和其他支持 Skills 的 Agent，也支持普通本地工作区和可选的 IMA 知识库。

## 开源运行架构

```text
GitHub Public Core
        ↓ 安装或升级
机构本地私有工作区
        ↓ 本地蒸馏与主管审核
机构运行时
        ↓
主管工作台 + 一线个人成长层
```

| 层级 | 保存什么 | 是否进入本仓库 |
| --- | --- | --- |
| Public Core | 通用方法、路由、脚本、Schema、安全规则 | 是 |
| 机构工作区 | 机构资料、团队名单、录音、截图、任务、审核账本 | 否 |
| 机构运行时 | 已审核事实、团队动作、群体洞察、内容资产 | 否 |
| 个人成长层 | 个人案例、训练和经验 | 否 |

一个工作区只绑定一个机构。普通用户始终安装官方公共 Core；只有无法共享机构工作区的设备，才需要可选的离线团队运行包。详细契约见 [V2.2 开源母体架构](docs/open-source-architecture.md)。

## 它解决什么问题

| 真实处境 | 你会得到 |
| --- | --- |
| 主管每天资料很多，不知道先处理什么 | 今日唯一团队断点、P0/P1/P2 待办、证据入口和复查标准 |
| 分析报告很多，但没有形成管理动作 | 患者推进、员工辅导、团队学习三层结论 |
| 不知道患者为什么不回复、没预约或没到院 | 沟通阶段、真实顾虑和流失节点诊断 |
| 患者说“太贵”“担心没效果”“不信任医院” | 顾虑类型、验证问题、安全回应和下一步动作 |
| 咨询师知道要回访，但不知道什么时候、为什么回访 | 分阶段回访计划、微信话术和停止条件 |
| 销冠经验在录音里，却无法复制给新人 | 销冠完整销售逻辑、阶段动作卡和 AI 陪练任务 |
| 团队主管每天听录音、做复盘、追踪员工进步 | 本地咨询管理工作台、员工单动作训练和复查队列 |
| 咨询师需要临时制作朋友圈或微信跟进素材 | 文案、案例示意、医院环境图、培训视觉卡和配图提示词 |
| 咨询师不会根据患者阶段写跟进、科普或私信内容 | 一条可直接使用的主推版本、无回复备选、禁用表达和知识缺口 |
| 团队能力更新后，一线成员各自的经验容易丢失 | 团队运行层与个人成长层合并，更新团队但保留个人积累 |

## 快速开始

第一次安装后只需要说：

```text
开始设置。
```

飞轮会确认角色、机构、科室和本人或团队，用一条真实材料验证后再请求一次自动运行授权。初始化采访已经内嵌，不需要另装第二个 Skill。

设置完成后，主管只保留四个入口：

```text
分析这一条。
分析今天全部咨询。
查看今天重点。
查看某个咨询师。
```

一线咨询师直接说：

```text
分析这段微信，告诉我患者现在处于哪个阶段，为什么没有继续回复。

患者说费用太贵，帮我判断他真正担心什么，并写出下一句微信回复。

患者已经爽约两次，帮我设计一次合适的回访。

陪我练一次“担心过去治疗失败”的患者，只训练一个动作。

根据这段微信写一条可以直接发送的跟进话术。

根据患者最担心的问题写一段朋友圈、患者科普或私信回复。
```

如果用户还没有机构资料或销冠蒸馏，基础咨询运行时也可以直接工作。它会使用通用咨询转化八步法，但不会编造本机构的价格、医生、地址、项目、疗效或治疗周期。

## 内容行动层

内容行动层不是独立文案工具。它先判断患者阶段、已观察顾虑和本次唯一推进目标，再读取已确认机构事实、团队能力、患者洞察和已审核内容资产，生成跟进话术、朋友圈、患者科普或私信承接素材。

本地文件夹和 IMA 是两种资料入口，不是两套知识库逻辑；两边资料统一进入同一审核与运行时。已有“咨询师内容工作台”八类目录可以通过 `scripts/map_content_knowledge.py` 只读识别并自动映射，不要求改名或搬运，映射也不等于事实审核。没有机构知识时仍可生成通用安全版，但不会补写真实医生、价格、地址、项目、活动、案例或疗效。

内容使用结果通过 `scripts/content_asset.py` 追加记录。只有已发送、存在正向反馈和证据引用，并经过主管审核的内容，才进入已审核团队资产；系统不会自动发送、发布或写入 CRM。

初始化本地资料时，Skill 只创建一个标准容器 `咨询转化工作区/`，并在其中生成截图所示的 `01_机构介绍` 到 `08_团队管理`、`_系统` 和 `README_先看这里.md`。初始化结束后会自动校验目录清单；没有通过校验，不会报告“初始化完成”。

## 咨询主管每日经营闭环

```text
发现团队断点
→ 找到优秀对照
→ 提炼销冠动作
→ 生成训练任务
→ 一线执行
→ 复查新样本
→ 验证行为和经营结果
→ 沉淀团队正式能力
```

本地工作台固定呈现六个模块：今日管理结论、今日管理待办、今日训练主题、重点员工与辅导进度、团队结果快照、女娲学习与能力复制。页面完全自包含、断网可用、只读；主管通过 Skill 指令更新任务，然后重建页面。

V2.1 默认“全量分析，重点呈现”：逐案报告保留在员工目录，主管首页只显示 P0 风险、每名员工一个问题、一个团队断点和正反代表案例。患者跨微信、录音的归并只提出建议，必须由主管确认。

```bash
# 首次采访确认后，原子建立机构、团队和工作区
python3 scripts/onboarding.py configure <目标目录> \
  --role manager --institution <机构> --department <科室> \
  --manager-name <主管> --members <成员列表>

# 查看首次设置还差哪一步
python3 scripts/onboarding.py status <工作区>

# 生成或刷新工作台
python3 scripts/generate_management_dashboard.py <工作区> --period today --date YYYY-MM-DD

# 每日复盘：扫描 → Agent 分批领取/提交 → 聚合
python3 scripts/run_nightly_cycle.py <工作区> --date YYYY-MM-DD
python3 scripts/daily_review.py claim <工作区> --owner <Agent标识> --date YYYY-MM-DD
python3 scripts/daily_review.py aggregate <工作区> --date YYYY-MM-DD

# 记录主管动作
python3 scripts/record_management_action.py <工作区> --task-id <任务ID> --event complete --note <说明>

# 一键创建完整的合成演示
python3 scripts/create_demo_management_workspace.py <目标目录>
```

生成页面位于：

`08_团队管理/04_团队报告/04_数据看板/咨询管理工作台.html`

## 基础运行时：不蒸馏也能用

AI咨询转化飞轮不是安装后只能等待资料蒸馏的空壳 Skill。它自带基础咨询运行时，安装后即可完成：

- 咨询转化八步法分析；
- 患者阶段判断；
- 真实顾虑识别；
- 费用、效果、信任、距离、时间和家人意见处理；
- 流失节点诊断；
- 到院前推进；
- 爽约和分阶段回访；
- 新人单动作陪练；
- 微信跟进文案和咨询视觉素材。

基础运行时的边界是：它提供通用咨询转化能力，不自动假设某家机构的具体事实。

## 蒸馏后：变成机构自己的咨询转化 Skill

主管第一次说“蒸馏销冠”或“更新咨询能力”时，Skill 会递归扫描当前工作空间，处理：

- 机构介绍、科室项目、医生和服务资料；
- 电话录音、微信聊天、私信和聊天截图；
- 长图切片与 OCR 结果；
- YouNavi 录音转写结果；
- 优秀、普通、失败、爽约和未到院案例；
- 团队会议、员工沟通和过程/结果数据。

蒸馏的主产物不是几句金句，而是可以被普通咨询师复制、被新样本验证的团队动作：

```text
销冠完整销售逻辑
    ↓
阶段判断与关键动作
    ↓
顾虑处理与流失修复
    ↓
新人陪练与团队辅导
    ↓
机构专属咨询转化能力包
```

每轮蒸馏同时沉淀三条证据链：

1. 个性化服务链：患者透露什么，咨询师如何识别、确认并提供针对性服务；
2. 安心感形成链：患者不确定什么，咨询师如何用事实、选择和路径降低不确定性；
3. 团队复制链：销冠动作如何被训练、采用、复查，并在普通咨询师新样本中稳定出现。

能力固定按 `候选经验 → 可训练动作 → 行为已验证 → 结果已验证 → 团队正式能力` 晋升。没有预约或到院数据时，只能验证行为，不宣称转化提升。

## 公共 Core、机构运行时与个人成长层

主管和一线始终使用同一个公共 Core，但加载的本地运行层不同：

```text
主管新增录音/聊天/数据
        ↓
机构本地蒸馏与审核
        ↓
发布机构运行时 Org-r.x
        ↓
主管与一线从工作区加载
        ↓
继续分析自己的案例与训练
        ↓
形成 Personal-v0.x
```

机构运行时更新时：

- 团队正式规则会更新；
- 个人历史案例和训练记录保留；
- 个人有效经验继续保留；
- 与新团队规则冲突的个人规则会标记为待重新验证；
- 个人经验不会未经主管审核自动进入团队规则。

## Dream Cycle

AI咨询转化飞轮的持续成长逻辑是：

```text
新增录音/微信/机构资料
        ↓
自动转写、OCR、去重和结构化
        ↓
识别团队断点与优秀对照
        ↓
生成训练任务并复查新样本
        ↓
验证行为和经营结果
        ↓
晋升并发布新的团队能力
        ↓
重建主管本地工作台
        ↺
```

IMA 资料源支持先建立清单、按价值排序、受限读取、配额感知、断点续传和受控缓存；IMA 限额不会阻塞本地资料处理。

## 隐私与安全边界

- 原始录音、微信聊天、截图和患者资料不进入公开 Skill 包；
- 外部 IMA 知识库不会被写入 Skill 默认内容；
- 患者姓名、电话、微信、病历和头像不会进入团队发布包；
- 未确认的价格、医生、地址、疗效、周期和活动不会被编造；
- 患者洞察只保留群体级决策状态，不生成患者个人画像；
- 不自动发送微信、不自动进行临床诊断、不自动做员工绩效定级；
- 生图能力必须由用户按照所在机构的审核要求使用，不能把虚构素材当作真实患者案例。

## 安装与更新

```text
开始设置。
```

```text
python3 scripts/doctor.py <工作区>
```

它会检查 Core 版本、工作区 Schema 和二者是否保持物理隔离。需要完全合成的演示环境时运行 `scripts/create_demo_management_workspace.py <目标目录>`；演示数据不能替代真实机构验证。

客户遇到问题时直接说“我要反馈问题”或“我要提建议”。安装和反馈说明都在 Skill 内；系统只在本地生成脱敏反馈卡，不自动上传。具体规则见 [单一安装包与反馈契约](references/distribution-and-feedback.md)。

## V2.2.1 版本定位

V2.2.1 收敛首次设置：角色必须是第一问，本地/IMA 不占用核心采访；问答顺序由可恢复状态机控制，人数不能冒充成员名单，没有工作区校验凭证时不能宣称创建成功。用户已经新建本地文件夹时，向导默认在其下创建 `咨询转化工作区/`；没有工作空间时先采访、后推荐并创建安全目录；没有本地文件能力时降级为临时单条分析。

## V2.2.0 版本定位

V2.2.0 不继续增加业务模块，重点把已有能力变成可持续维护的开源产品：

```text
单一 VERSION 真源
+ 公共 Core / 私有工作区 / 机构运行时 / 个人层分离
+ 更新不覆盖用户数据
+ 确定性公共包构建与文件哈希
+ GitHub CI 与 Release 自动化
+ GitHub 与国内渠道只分发同一个 `.skill`
+ 本地脱敏反馈卡与服务人员回流链路
+ 开源贡献、安全报告和版本记录
+ 单入口 Skill 按任务渐进加载
```

V2.1.3 的可信审核、隐私扫描、长图 OCR、每日队列和运行时完整性机制完整保留。
