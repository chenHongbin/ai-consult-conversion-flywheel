# 医疗视觉路由｜全部调用 API

内容路由只决定每页怎样编译提示词，不决定成图引擎。所有页面都通过当前配置的老张 API 或 HiAPI 生成。

## 项目模式

| 模式 | 识别条件 | API 调用策略 |
| --- | --- | --- |
| quick | 单平台、单页 | 调用一次生成单图 |
| series | 同平台多页 | 先调用一次生成封面，确认后逐页调用 |
| multiplatform | 同一主题多个平台 | 每个平台单独调用，锁定核心结论和视觉体系 |
| infographic | 机制、流程、清单、对比、数据为主 | 减少文字，按页面结构编译信息图提示词 |

## 页面角色

- `hook`：封面钩子，只讲一个结论；
- `misconception`：误区与更安全表达；
- `mechanism`：医学机制关系，必须有来源；
- `flow`：行动步骤或内容流程；
- `checklist`：可收藏的观察或准备清单；
- `comparison`：并列比较，不做虚构疗效前后对比；
- `data`：数据证据，必须有来源和口径；
- `doctor-ip`：医生观点封面，不虚构医生身份；
- `story`：教育性场景，不冒充真实患者；
- `event`：活动信息，不生成假二维码；
- `quote`：观点金句；
- `action`：下一步提醒，不替代诊疗建议。

## 六套视觉体系

| style | 适合场景 |
| --- | --- |
| `clinical-swiss` | 机制、流程、清单、对比、数据 |
| `patient-editorial` | 患者友好科普、误区、清单 |
| `doctor-magazine` | 医生 IP、观点、故事 |
| `research-report` | 研究、数据、证据、机制 |
| `warm-lifestyle` | 患者生活方式、照护、故事 |
| `brand-event` | 医疗品牌活动、直播、会议 |

这些风格会编译进每一页 API 提示词。系列图保持相同风格、颜色、眉题和画面质感，但图像模型仍可能产生漂移，必须目检。

## 首张确认

- 多页、多平台项目默认 `--pilot`，只产生一次付费 API 调用；
- 首张确认标题、主视觉、颜色、质感和中文可读性；
- 确认后使用 `--all` 逐页调用；
- 只重做有问题的页面，不默认整套重跑。
