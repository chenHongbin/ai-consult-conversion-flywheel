# v1.6 发布说明：可靠资料处理、影子试用与统一原子发布

## 为什么升级

首次蒸馏的真实门槛不是“有没有蒸馏提示词”，而是能否把工作空间里的资料尽可能完整、可追溯地变成证据，并且让用户在第一轮处理后立即看到可用结果。v1.6 针对三个断点升级：

1. 不能只处理已经转写好的单条录音；
2. 一张长图、一个转写失败不应该阻塞整批；
3. 咨询能力、机构知识和患者洞察不能各自更新、彼此错版。

## 三项核心变化

### 1. 可靠资料处理

- 全量扫描当前工作空间，识别音频、图片、微信 HTML、PDF、DOCX、XLSX 和 PPTX；
- 音频通过 YouNavi 批量转写；长图先切片再 OCR；文档先提取已有文本；
- 每条派生文本通过 manifest 回链到原始文件；
- OCR 记录高/中/低质量和分数，低质量材料仍保存但不能单独证明规则；
- 转写、OCR 或文档提取失败进入失败记录并继续其他文件；
- `prepare_distillation_batch.py` 同时读取 OCR、转写和文档提取清单，避免“已经处理但没有进入蒸馏批次”。

### 2. 处理完立即影子试用

`run_full_distillation.py` 在生成标准化批次后自动调用 `run_shadow_analysis.py`，按去重簇和样本角色选出少量代表案例，生成影子试用队列。Agent 按咨询转化八步法输出复盘：阶段、需求、顾虑、断点、证据、下一步和待确认事实。

影子试用的定位是“先让用户看到系统能不能工作”，不是把单条成功案例直接升级为机构规则，也不改变当前 active 能力包。

### 3. 三类能力统一原子发布

咨询能力、机构知识、患者洞察仍然分别候选、分别审核，但发布时统一由 `publish_release.py` 生成一个 release，记录三类组件的版本、哈希、作用范围和前一版。团队包必须绑定这个 release 才能构建；`rollback_release.py` 会同步恢复三类组件，避免版本错配。

## 运行顺序

```bash
python3 scripts/run_full_distillation.py <工作空间根目录> --run-transcription --run-ocr
# Agent 读取影子队列和蒸馏批次，生成并审核三类候选，再分别运行三类 commit 脚本
python3 scripts/publish_release.py <工作空间根目录> --version v1.6
python3 scripts/build_team_skill_package.py <工作空间根目录> --output-dir <发布目录> --institution <机构> --department <科室>
```

不满足统一 release 时，团队包构建会拒绝；需要回滚时：

```bash
python3 scripts/rollback_release.py <工作空间根目录> --previous
```

## 边界

- v1.6 不把 IMA 示例资料写入 Skill；
- 不自动发送微信、不自动绩效定级、不替代医生判断；
- 不把低质量 OCR 当成高置信度证据；
- 不因为路径写着“已到/未到”就当成事实，结果仍需从内容或数据确认；
- 不自动把影子试用结论写进 active 版本。
