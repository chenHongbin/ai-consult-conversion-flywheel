# 内容行动层运行规范（V2.1.3）

## 目标

内容行动层不负责“多写几篇文案”，而是把患者当前决策卡点变成一条可以安全执行、可以记录结果的下一步内容。它属于咨询分析的下游，也允许一线直接通过自然语言调用。

用户只安装 AI咨询转化飞轮。不要要求用户另装“咨询师内容工作台”，也不要要求先建立第二套八文件夹知识库。

## 自然语言入口

以下任务进入 `content_action`：

- 帮我写跟进话术；
- 写条朋友圈；
- 写患者科普；
- 写私信或评论区回复；
- 根据这条咨询生成下一步内容。

用户明确要求图片、配图、海报、案例图或环境图时，以 `visual_content` 为主路由；内容行动层只提供配套文案和事实边界。

## 内容处方

生成前在后台形成一张内容处方：

```text
content_type
patient_stage
observed_concern
single_objective
channel
verified_knowledge_refs
missing_fact
voice_scope: personal / institution / generic
clinical_and_compliance_boundary
single_cta
```

只有影响正文的缺口才向用户追问，而且一次只问一个。内部处方不要求用户先确认；先生成主推版本，用户再要求调整。

## 知识来源与运行时

本地文件夹和 IMA 是两种资料入口。两者必须进入同一来源清单、去重、脱敏、候选、审核和发布链路，不得分别维护互相冲突的“本地答案”和“IMA 答案”。

内容生成按以下优先级读取：

```text
医疗安全与隐私
> 已确认机构事实
> 团队正式咨询规则
> 已审核内容资产与机构口吻
> 个人已验证表达风格
> 通用基础方法
```

原始录音、截图、聊天和 IMA 媒体不是运行时事实。只有为了核对证据或生成候选时才受控读取。

没有机构知识时仍然可以生成，但必须使用 `generic/base_only`：不出现真实医生、价格、地址、项目、活动、案例、疗效或治疗周期；只提示一个最关键的待补事实，不让用户先去整理知识库。

## 原“咨询师内容工作台”资料映射

如果识别到已有八类目录，后台按逻辑映射，不移动、不改名：

| 原分类 | 飞轮逻辑位置 |
|---|---|
| 机构基础与信任背书 | `01_机构介绍` |
| 项目/病种知识 | `02_科室项目与服务` |
| 咨询方法论、合规边界 | `03_咨询流程与标准` |
| 标杆案例、销冠语料 | `04_优秀咨询案例` |
| 黑榜、异议、聊死案例 | `05_普通失败与未预约案例` |
| 训练、主管反馈 | `06_团队培训与反馈` |
| 朋友圈、话术和科普成品 | `07_我的产出/07_内容行动工作台` |
| 团队记录、审核和结果 | `08_团队管理` 与 `_系统/内容资产` |

映射只是资料索引，不代表原文件中的说法已经通过事实审核。

本地目录或 IMA 文件夹名称需要生成可重建映射清单时，读取 `references/content-knowledge-mapping.json` 并使用 `scripts/map_content_knowledge.py`。脚本只写 `_系统/内容资产/knowledge-mapping.json`，不修改来源目录。

## 四类内容合同

### 跟进话术

默认只显示：

```text
可以直接发：……
如果对方没回复：……
不要这样说：……
```

正文只推进一个动作。回访必须有理由、时间和停止条件；不能用虚假名额、优惠、专家或紧迫性制造压力。

### 朋友圈文案

结构是“一个主题 + 一个可信事实 + 一个低压力行动入口”。默认给一条主推文案和配图方向；用户要求差异化时，再提供专业、温度、行动三个不同角度。不得只换同义词制造伪多版本。

### 患者科普

先回答患者当前问题，再解释可确认知识和下一步。语言口语化、短句化；不替代诊断、用药、检查解释或治疗方案。涉及临床结论时转执业人员。

### 私信承接

根据平台提供评论区短回复、私信承接和加微信后第一句。先给价值和来源说明，再提供可选择的行动；不得隐瞒收集联系方式的用途。

## 口吻与同质化

- 机构口吻只来自已审核机构内容或管理者确认的风格规则。
- 个人口吻来自本人已确认或已验证内容，不反向覆盖团队规则。
- 没有口吻资料时使用清楚、可信、克制的通用表达。
- 默认只交付主推版本；用户或主管需要团队防撞稿时，再生成三个不同沟通角度。

## 反馈与内容资产

每条需要追踪的内容使用稳定 `asset_id`，并通过 `scripts/content_asset.py` 记录追加式事件：

```text
draft → revised → sent / skipped
                 ↓
 reply_quality=positive / appointed / arrived
                 ↓
              candidate
                 ↓ 主管审核回执
       pending_publish / revise / rejected
                 ↓ 统一 release
              available
```

`unknown` 必须保持未知，不能转换为 `no`。生成内容不自动写入正式知识。只有同时满足以下条件，才允许进入已审核内容资产：

1. 有已发送记录；
2. 回复质量明确为 `positive`，或预约/到院结果为 `yes`；单纯 `replied=yes` 不足以证明有效；
3. 正文和结果证据都能解析到当前工作区内的真实文件；
4. 有明确主管审核人。

批准内容仍要保留冻结正文、内容哈希、适用机构、科室、病种/项目、阶段、顾虑、渠道、时间和失效条件；一次有效不等于跨场景通用。`reject/revise` 会从当前已审核投影移除资产；只有新的统一 release 才能让批准内容进入团队运行时。

## 主管和一线的不同视图

一线默认只看到正文、备选动作和风险提醒。主管可以看到知识引用、内容状态、患者反馈、候选原因和审核动作。主管批量分析当天咨询时，先对重点患者给出内容处方，不自动批量发送。

## 安全与外部动作

- 不编造患者、医生、机构、案例、数据、疗效或活动。
- 不把 AI 示意内容包装成真实案例。
- 姓名、电话、微信、头像、病历号和原始患者文本不得写入内容资产事件日志。
- 内容生成和记录均不等于发送、发布或写入 CRM；任何外部动作都需要用户明确授权并由对应宿主返回真实回执。
