# V2.1 每日全量咨询复盘运行时

## 用户入口

普通用户只需要四个动作：

- 建立我的机构；
- 分析这一条；
- 分析今天全部咨询；
- 查看今天重点。

不要要求用户理解队列、对象 ID、提示词、哈希或版本号。

## 单条分析

直接上传微信长截图、录音或文本时：

1. 完成切片/OCR或转写，恢复消息顺序和说话人；
2. 读取 [v2.1-case-report-contract.md](v2.1-case-report-contract.md)；
3. 生成逐案报告；
4. 一线只看到自己的报告和一个训练动作；
5. 主管可以把案例加入员工训练或团队复盘。

本地可读取文件通过同一队列登记：

```bash
python3 scripts/daily_review.py register <工作区> --source <文件> --employee-id <员工编号> --employee-name <姓名> --date YYYY-MM-DD --medium audio|image|wechat|text|chat
python3 scripts/daily_review.py claim <工作区> --owner <Agent标识> --task-id <登记返回的任务ID>
```

直接上传和员工文件夹批量上传必须使用同一逐案合同，不能维护两套分析逻辑。

## 每日批量流水线

### 1. 扫描并建立任务

```bash
python3 scripts/run_nightly_cycle.py <工作区> --date YYYY-MM-DD
```

该命令只说明“发现并登记了材料”，不能说明分析已经完成。

### 2. Agent 领取有限批次

```bash
python3 scripts/daily_review.py claim <工作区> --owner <本次Agent标识> --date YYYY-MM-DD --batch-size 20
```

领取后逐项处理。图片先执行长图切片和 OCR；录音先转写并保留时间点；文本直接读取。对每项生成符合逐案合同的 JSON。

若任务类型为 `patient_case_bundle_analysis`，读取 `source_items` 和 `conversation_ids` 中全部已确认材料，生成一份跨微信/电话的患者组合报告；分别保留各渠道证据位置，指出阶段变化、顾虑是否变化、前后动作是否一致和当前统一下一步。不要把未确认材料加入患者包。

如果领取结果带有 `current_training`，本次分析必须复查该训练动作：在 `training_followup` 中记录是否出现及证据位置。出现一次标记“已出现”，在至少两个独立新患者案例中重复出现才标记“已稳定”。当前训练未关闭前，不再为该员工创建第二个进行中训练。

主管确认训练已完成或决定更换训练时，先关闭当前动作：

```bash
python3 scripts/daily_review.py close-training <工作区> --action-id <训练ID> --reviewer <主管> --note <原因>
```

关闭后，后续聚合只有在新短板达到证据门槛或命中 P0 时才建立新的唯一训练。

系统根据风险、拒绝/流失、关键阶段停滞、新问题和典型案例要求深析。主管调整某项优先级时执行：

```bash
python3 scripts/daily_review.py prioritize <工作区> --task-id <任务ID> --deep yes|no --reviewer <主管>
```

`no` 只能移除普通深析，不能取消 P0 风险深析。

### 3. 完成或记录失败

```bash
python3 scripts/daily_review.py complete <工作区> --task-id <任务ID> --analysis-json <分析JSON> --owner <本次Agent标识>
```

无法读取时：

```bash
python3 scripts/daily_review.py fail <工作区> --task-id <任务ID> --reason <原因> --owner <本次Agent标识>
```

疑似跨患者、隐私泄露或材料不可安全使用时增加 `--quarantine`。不要用空报告代替失败记录。

### 4. 继续领取直到本次窗口结束或队列清空

每批完成后再次 `claim`。返回空任务表示当前没有可领取项。夜间窗口结束时保留未完成状态，下次继续，不得把未完成任务标成已处理。

### 5. 生成四层交付

```bash
python3 scripts/daily_review.py aggregate <工作区> --date YYYY-MM-DD
python3 scripts/generate_management_dashboard.py <工作区> --period today --date YYYY-MM-DD
```

最终交付：逐案报告、员工日报、团队日报；重复短板达到证据门槛或命中 P0 时生成单动作训练卡。单案报告仍给出本案辅导动作，但不凭一个普通案例启动正式员工训练。主管首页优先显示 P0 风险、每人一个主要问题、团队共同断点和正反代表案例，不要求主管阅读全部逐案报告。

## 患者归并确认

当状态中出现 `suggested` 时，只向主管展示建议理由和涉及的对话。主管确认后执行：

```bash
python3 scripts/daily_review.py group <工作区> --suggestion-id <建议ID> --decision confirmed --reviewer <主管>
```

拒绝则使用 `--decision rejected`。未经确认，不得把多个对话写成同一个患者故事。

## 夜间调度

WorkBuddy/Codex 适配器只有在用户明确授权一次后才能建立定时任务。默认建议 22:30，本地时区；用户可自然语言修改。Claude/Trae 没有可用调度器时保留完全相同的手动流水线，并明确说明尚未自动运行，不得假装已安装定时任务。

## 完成定义

只有同时满足以下条件，才可以说“今天的复盘已完成”：

- 所有有效材料已完成或明确进入失败/隔离区；
- 每个已完成案例有可追溯逐案报告；
- 员工日报、团队日报和训练卡已生成；
- 未确认患者归并、失败任务和 P0 风险已单独显示；
- 没有业务结果时未输出转化提升结论。

## 状态体检与安全修复

夜间结束或发现“显示完成但找不到报告”时运行：

```bash
python3 scripts/daily_review.py audit <工作区>
```

需要修复已过期租约或“完成但产物缺失”的任务投影时，管理者确认后运行 `--repair`。修复只把任务退回待处理并清理过期租约，不删除原始材料、不合并患者、不修改能力包。业务结果越界和一个员工多个活动训练只报告问题，等待人工判断。
