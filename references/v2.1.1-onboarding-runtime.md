# V2.2.1 三阶段首次设置与初始化采访运行时

## 目标

新用户只安装 AI咨询转化飞轮。第一次使用时，先通过不超过 5 轮的核心采访确认角色、机构作用域、本人或团队，并用一条真实材料验证。用户看到第一份可信报告后，再申请一次自动运行授权。

初始化采访不是独立问卷，也不要求用户安装第二个 Skill。采访答案直接驱动飞轮配置；已有答案不重复询问。

## 三阶段产品体验

### 第一阶段：让我先了解你

核心采访不超过 5 轮，一次只问一个问题。后台必须用 `scripts/onboarding.py interview-start` 与 `interview-answer` 保存当前步骤；Agent 不得凭记忆重排问题。

### 第二阶段：确认并准备好工作区

第五轮后展示一次摘要，同时用普通语言显示“工作区将创建在：当前文件夹/咨询转化工作区”。只有用户确认后才写入。用户如果已经新建并打开一个空白本地文件夹，直接把当前文件夹作为父目录候选，不再追问路径；若没有可用本地文件夹，才请用户先选择或新建一个。

没有当前工作空间时不阻塞第一阶段。后台用 `interview-start --host <宿主>` 建立24小时有效的临时采访状态；获取机构名称后推荐 `用户文档/AI咨询转化飞轮/<机构>/咨询转化工作区`。摘要页提供三个普通语言动作：确认创建、换个位置、先临时分析一条。位置选择不计入核心五问。

如果用户把当前文件夹直接命名为 `咨询转化工作区`，就使用该文件夹本身，不再创建同名嵌套目录。其他名称一律视为业务父目录，在其下创建标准子目录。宿主不能真实运行脚本或访问本地文件时，不能显示“工作区已创建”，只能进入下面的临时分析模式。

### 临时分析模式

宿主没有本地文件能力，或用户在摘要页选择“先临时分析一条”时，基础运行时可以分析当前上传的截图、录音转写或文本。前台固定说明：本次结果只服务当前对话，不保存团队历史，不生成每日重点，不跟踪个人成长，也不申请自动运行。用户以后说“继续设置”时，恢复摘要并重新确认工作区位置。

### 第三阶段：先分析一条，确认真的能用

工作区校验成功后，请用户上传刚才提到的微信、录音或文本，生成第一份真实报告并询问是否符合实际。之后才询问自动运行；宿主不支持自动化时明确进入手动模式。

## 固定前台顺序

### 0. 自动盘点

只读检查当前 Core 版本、现有工作区、角色、机构、成员、OCR、YouNavi、首条报告和自动化状态。已有信息只汇总确认，不重问。检测到 V1.x/V2.0 旧工作区时继续使用原工作区并只补缺失项；同时安装多个同名版本时要求宿主只保留最高版本，不能混合执行。

### 1. 角色

只问：

> 你主要是自己做患者咨询，还是管理一个咨询团队？

主管和一线使用不同权限、成员流程和首页入口。

### 2. 机构作用域

只问：

> 你负责哪家机构、哪个科室或部门？有主推项目也可以一起告诉我。

医生、价格、疗效、资质和案例结果不能因为一次口述自动成为机构事实。

### 3. 日常工作与当前问题

主管优先确认听录音、看微信、辅导员工和团队复盘中的主要工作；一线优先确认微信回复、电话邀约、回访和现场咨询。这个答案只影响入口排序和首次重点，不产生绩效结论。

### 4. 本人或团队

主管可以粘贴名单、上传 Excel 或名单截图。Agent 先识别成 `员工编号_姓名` 列表，只让用户处理重名和识别不清项；可以先添加一人试用。一线只确认本人称呼和可选员工编号。

### 5. 第一条真实材料

只确认用户是否有一张微信长截图、一通录音或一段文字准备验证，不在采访草稿中保存患者内容。先完成采访汇总确认和标准工作区建立，再让用户实际上传，并用同一个 V2.1逐案合同处理。

第一次报告只显示患者卡点、咨询师一个关键动作、下一步和证据。随后问“这个判断是否基本符合实际”。不符合时定位机构作用域、员工归属、OCR/转写或分析判断中的具体问题，不能直接宣布设置完成。

## 确认与写入

不要每题重复请求写入权限。采访过程中保存草稿；结束时只展示一次摘要，让用户确认机构、部门、角色、团队和当前问题。患者原文、机构敏感事实和外部文件写入仍单独确认。

确认后执行：

```bash
python3 scripts/onboarding.py interview-confirm <用户选择的根目录> --confirmation confirm
```

脚本会创建并校验标准工作区、写入唯一结构化画像、生成可读画像，并把自动化保持为“未授权”。普通用户不看到命令、对象 ID 或配置路径。

如果用户要修改摘要，运行 `interview-confirm --confirmation revise --revise-step <字段>`，只回到对应问题，不清空已经确认的其他答案。

## 后台调用示例

```bash
python3 scripts/onboarding.py interview-start <当前本地文件夹> --host younavi
# 没有当前工作空间：
python3 scripts/onboarding.py interview-start --host workbuddy
python3 scripts/onboarding.py interview-answer <当前本地文件夹> --step role --role manager
python3 scripts/onboarding.py interview-answer <当前本地文件夹> --step organization --institution <机构> --department <科室>
python3 scripts/onboarding.py interview-answer <当前本地文件夹> --step daily_work --daily-work <日常工作> --current-problem <当前问题>
python3 scripts/onboarding.py interview-answer <当前本地文件夹> --step identity --manager-name <主管> --members <成员名单>
python3 scripts/onboarding.py interview-answer <当前本地文件夹> --step first_case --first-case ready
```

无工作空间时，宿主隐藏脚本返回的 `session_id`，后续用 `--session-id` 继续。摘要确认可以执行：

```bash
python3 scripts/onboarding.py interview-confirm --session-id <内部ID> --confirmation confirm
python3 scripts/onboarding.py interview-confirm --session-id <内部ID> --confirmation confirm --workspace-root <用户选择的位置>
python3 scripts/onboarding.py interview-confirm --session-id <内部ID> --confirmation temporary
```

## 第一条验证

登记首条材料：

```bash
python3 scripts/onboarding.py register-first-case <工作区> \
  --source <文件> --date YYYY-MM-DD --medium image|audio|wechat|text|chat
```

随后按照 [v2.1-daily-review-runtime.md](v2.1-daily-review-runtime.md) 领取并完成任务。报告真实存在后记录用户判断：

```bash
python3 scripts/onboarding.py verify-first-case <工作区> \
  --judgment accepted
```

用户暂时没有材料时可明确执行 `defer-first-case`，但完成页必须显示“首条语义质量待验证”。

## WorkBuddy 自动运行

用户看到第一份报告后再问：

> 要不要每天自动处理新增材料？默认晚上 22:30，也可以换时间。只需要授权一次。

先执行 `request-automation` 生成宿主请求。若 WorkBuddy 提供 `automation_update`，将请求字段原样交给该工具。把工具的真实结果保存为 JSON，再执行 `verify-automation --receipt <回执>`。

只有回执包含活动状态、真实自动化 ID，并且时间和工作区匹配时，脚本才把状态改为 `verified`。没有宿主工具时，不得手写假回执；让用户选择 `manual-mode`，保留“分析今天全部咨询”的同合同手动入口。

## WorkBuddy 画像投影

飞轮工作区 `_系统/首次设置/confirmed-profile.json` 是唯一真源。需要让 WorkBuddy 使用个人偏好和机构额外红线时，先预览：

```bash
python3 scripts/onboarding.py project-workbuddy <工作区> \
  --user-file <USER.md> --memory-file <MEMORY.md>
```

用户确认后增加 `--apply`。脚本只更新带管理标记的区块并先备份，不修改 `SOUL.md`，不覆盖文件其他内容。

## 完成定义

只有角色、机构、本人/团队、标准工作区、首条验证状态和自动化选择全部明确，才执行：

```bash
python3 scripts/onboarding.py complete <工作区>
```

主管完成后只显示四个入口：分析这一条、分析今天全部咨询、查看今天重点、查看某个咨询师。一线只显示：分析这一条、帮我回复、安排回访、陪我练一遍。

## 渐进补档

渠道、常见顾虑、高频场景、输出偏好、机构额外红线、考核口径和学习目标不阻塞首次使用。只有缺失字段真正影响当前任务时才追问一个问题。用户说“更新我的设置”“记住这个偏好”“换科室了”“新增咨询师”时，再更新结构化画像并重新投影。
