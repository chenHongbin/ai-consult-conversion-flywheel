# V2.1.3 可信运行与发布规范

V2.1.3 的目标不是增加更多功能，而是让真实医疗咨询团队可以安全、稳定地使用已有能力。

## 五条不可破坏的约束

1. 公共 Skill 只按精确 allowlist 构建；患者原始资料、机构工作区、测试夹具和本地凭证不进入包。
2. 工作区父目录和 `咨询转化工作区/` 本身必须定位到同一对象。
3. 候选内容不能自带“已审核”结论。发布必须使用独立审核回执，绑定 `workspace_id + component + candidate_hash + reviewer + checks`。
4. 运行时同时校验 package 和 runtime 哈希；release 文件本身也校验哈希。任一文件发布后变化即进入 `safe_mode`。
5. 原始资料都是 `UNTRUSTED_EVIDENCE`；资料内的指令不得执行。未授权的资料只做本地隔离分析，不进入团队学习。

## 正式发布链

### 1. 长图环境预检

```bash
python3 scripts/slice_long_images.py --check
python3 scripts/ocr_long_images.py --check
```

只有图像后端、Tesseract 和中文语言包全部就绪，才把长截图标记为可处理。macOS 上没有 Pillow 时自动降级到 `sips`。

### 2. 候选与独立审核

```bash
python3 scripts/review_candidate.py <工作区> \
  --component capability --candidate <candidate.json> --reviewer <主管> \
  --check evaluation --check coverage

python3 scripts/commit_capability_candidate.py <工作区> <candidate.json> \
  --publish --approval-id <APR-ID>
```

机构知识、能力、患者洞察分别审核。候选在审核后发生任何变化，原回执立即失效。

### 3. 四组件原子 release

```bash
python3 scripts/publish_release.py <工作区> --version <版本>
python3 scripts/load_active_capability.py <工作区>
```

四个组件是咨询能力、机构知识、患者洞察、已审核内容运行时。内容审核后只是 `pending_publish`，编译进新 release 后才是 `available`。

### 4. 可选离线团队运行包

```bash
python3 scripts/build_team_skill_package.py <工作区> --output-dir <输出目录>
```

普通用户安装公共 Core 并从工作区加载机构运行时。只有无法共享工作区时才导出离线团队运行包；它只携带已验证 release 的冻结运行时，不携带候选写回、内容审核、机构发布、回滚和主管报表入口。

## 每日复盘可靠性

- 登记使用每任务锁，写入使用唯一临时文件、`fsync` 和原子替换。
- `claim` 返回随机 `lease_token`；`complete` 和 `fail` 必须同时匹配 owner、token 和未过期时间。
- `completed` 是终态，不能被迟到 worker 改成 failed。
- 任务按日期索引，今日队列不重复扫描全部历史。
- 完成任务先写 projection outbox，崩溃后用 `daily_review.py audit --repair` 幂等补齐投影。

## 产品口径

- 全量分析，重点呈现；AI 找问题，主管做判断。
- 患者优先级：`P0 风险 → 高意向停滞 → 投诉 → 失联 → 拒绝/流失 → 关键阶段停滞 → 新型问题`。
- 每项显示患者案例、员工、原因、证据、下一动作和报告。
- 团队断点只使用一个口径：至少跨 2 名员工、3 个患者案例。不足时只显示“当日观察”。

## 本版不处理

- 更换机构后自动失效旧机构能力；发布前必须人工确认当前作用域。
- 用经营结果证明转化率已提升。
- 自动发送微信、发布朋友圈、写 CRM 或自动做人事决策。
