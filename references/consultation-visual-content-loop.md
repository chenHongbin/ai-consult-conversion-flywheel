# 咨询视觉弹药闭环

## 第一性原理

咨询师要的不是“会不会做图”，而是当患者卡在一个具体决策点时，能不能马上给出一份更容易理解、记住和继续沟通的视觉材料。

因此，视觉能力属于咨询转化的“产”这一层，挂在对话分析之后：

```text
对话分析
→ 判断患者阶段与主要顾虑
→ 确定一个下一步动作
→ 生成朋友圈文案
→ 生成微信跟进文案
→ 判断是否需要视觉解释
→ 调用医疗生图引擎
→ 输出图片、适用场景和发送建议
→ 回填患者反馈
```

图片不是独立内容部门，也不是每次都堆一张海报。它必须服务一个具体动作，例如：解释流程、降低陌生感、帮助理解检查准备、建立专业信任或推动下一次回复。

## 每次对话分析的素材包

当用户提供电话、微信、私信或录音并要求分析时，默认在复盘卡后附一个“咨询素材包”：

1. 当前患者顾虑和证据；
2. 朋友圈短文案（适合公开触达）；
3. 微信下一步文案（只推进一个动作）；
4. 推荐视觉类型；
5. 一条可直接执行的生图提示词；
6. 图片用途、比例和需要绑定的机构事实；
7. 反馈字段：已发送/未发送、患者反应、下一步结果。

如果当前对话只是内部复盘、没有明确触达场景，先生成文案和视觉 Brief；用户说“直接出图”或系统判断图片能明显降低当前顾虑时，直接调用生图引擎，不再要求用户重复确认。

## 视觉路由

| 患者卡点 | 推荐素材 | 默认目的 |
|---|---|---|
| 不理解为什么要检查或如何到院 | 检查/到院流程卡、准备清单 | 降低行动成本 |
| 对费用、流程或服务不清楚 | 服务流程说明卡、项目选择示意 | 降低信息不确定性 |
| 担心医院/医生不可信 | 医生科普封面、诊室接诊示意、机构环境示意 | 建立专业感与熟悉感 |
| 想看案例但没有授权真实案例 | 匿名咨询案例示意、过程路径图 | 帮助理解过程，不伪装疗效证据 |
| 用户明确提供并授权真实案例照片 | 原图脱敏、裁切、排版或合规编辑 | 整理真实素材，不改变事实 |
| 需要朋友圈持续触达 | 一句话主题海报、患者教育卡 | 提醒与持续沟通 |
| 咨询师需要学习 | 普通回复/优化回复对比图、动作拆解图 | 团队培训 |

## 三个不可混淆的素材类型

### 1. 真实案例整理

只有用户提供且确认有权使用的真实照片，才可以整理为真实案例素材；必须去除姓名、电话、微信、头像和病历信息，不改变病情事实，不新增疗效结论。

### 2. 案例示意图

没有授权真实照片时，可以直接生成匿名人物、抽象皮肤状态、治疗流程或就医过程的示意图。画面和文案必须明确它是“AI示意图/案例示意”，不能称为本院真实患者前后对比。

### 3. 机构环境示意

没有真实院区照片时，可以生成“医疗机构环境示意”或“门诊氛围示意”。不能把生成的热闹大厅、医生接诊或患者排队图说成真实院区实时场景。用户提供真实环境照片时，优先做授权范围内的优化。

## 引擎调用

现有 `skills/medical-image-studio/` 是嵌入式视觉引擎，不是第二个学员入口。它保留：

- 老张 API / HiAPI 配置与路由；
- `quick / series / multiplatform / infographic` 项目模式；
- 医疗视觉路由、比例、文字容量和 API 生成；
- dry-run 预检、首张试生成、批量延展和 QA 清单。

首次使用生图时，在用户本地终端运行：

```bash
node <Skill目录>/skills/medical-image-studio/scripts/medical-image.mjs --doctor
node <Skill目录>/skills/medical-image-studio/scripts/configure.mjs
```

Key 只保存在用户自己的本机配置中，不放入工作区、提示词、日志或 Skill 包，也不通过聊天收集。

文生图快速入口：

```bash
node <Skill目录>/skills/medical-image-studio/scripts/medical-image.mjs \
  --prompt "最终提示词" --aspect-ratio 3:4 --resolution 2K
```

当前嵌入引擎的服务商适配器实际以文生图为主；图生图必须在服务商支持安全的参考图上传接口后再启用，不能把“文字描述参考图”冒充成已经上传了原图。用户要处理真实患者或真实医院图片时，先走授权、脱敏和适配器能力检查。

如果当前 Agent 环境本身提供受控的图片编辑能力，则可以把用户明确指定的本地图片作为参考图执行图生图/图片编辑；调用前仍需检查授权和脱敏，调用后保留原图不变。若当前环境只有嵌入式 API 文生图，就明确使用“示意图/重新生成”，不得静默声称完成了图生图。

## 输出目录

用户只看到一个入口：

```text
咨询转化工作区/07_我的产出/06_咨询视觉素材/
├── 01_朋友圈文案与配图/
├── 02_微信跟进素材/
├── 03_案例与过程示意/
├── 04_医院环境与医生科普/
└── 05_团队培训视觉卡/
```

项目文件、提示词、服务商请求、QA 和反馈记录放在后台：

```text
咨询转化工作区/_系统/视觉生成/
```

原始患者照片和原始聊天截图不复制到发布包；工作区只保存用户明确指定的受控原始资料和脱敏后的成品。

## 三个可直接试跑的提示词

### 示例一：皮肤问题案例示意图

```text
制作一张 3:4 的咨询案例示意图，用于微信沟通，面向一位担心“以前反复治疗、看不到改善”的皮肤问题患者。画面采用匿名成年人侧身局部皮肤示意，不出现可识别脸部、姓名、病历或真实患者照片。用左右两栏表达“就医前的困扰”与“经过专业评估后更清楚下一步”，只表现状态变化和咨询路径，不表现真实治疗前后疗效，不生成具体疾病诊断、治愈、疗程或效果数字。整体温和、可信、医学科普风。图片内只放短字：“先了解问题，再决定下一步”“AI案例示意图”。
```

### 示例二：门诊环境氛围示意图

```text
制作一张 1:1 的医疗机构门诊环境氛围示意图，用于朋友圈建立专业与安心感。画面是明亮整洁的现代门诊大厅，前台、候诊区和医护人员自然忙碌但不过度拥挤，呈现有秩序、有服务、有咨询流程的感觉。不要使用真实医院名称、真实医生、真实患者、真实院区标识或虚构排名，不要暗示这是某家医院的实时客流。图片内只放短字：“到院前，先把流程了解清楚”“门诊环境示意图”。
```

### 示例三：医生接诊与微信跟进素材

```text
制作一张 3:4 的医疗咨询跟进卡，用于微信发送给正在犹豫是否到院的患者。画面表现一位不指向真实个人的医生或医护人员在诊室中认真倾听患者，桌面有记录本和流程卡，氛围专业、耐心、无压迫感。不要生成可识别真实医生、真实患者、医院资质、疗效承诺、检查结果或价格。图片内只放短字：“先把情况说清楚，再决定下一步”“AI场景示意图”。
```

三条提示词都可以直接通过 `medical-image-studio` 的快速入口试跑；实际发送前，咨询师只需把文案、机构事实和图片用途绑定到当前对话，不需要理解内部项目文件。
