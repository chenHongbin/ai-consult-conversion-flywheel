# 单一安装包与用户反馈契约

GitHub 是公共源码和版本真源，不是所有终端用户必须访问的安装渠道。快商通、WorkBuddy、客户成功团队、企业网盘或服务人员都只分发同一个官方 `.skill`。

## 一个真源，多条渠道

每个 Core 版本只有一个正式交付物：

```text
AI咨询转化飞轮_vX.Y.Z.skill
```

不区分普通版、团队版、渠道版或“带说明书版本”。渠道不得重新压缩、编辑或包装 `.skill`；需要修改内容时升级版本、重新测试和重新构建。

## 客户最短路径

客户只需要：

1. 接收 `AI咨询转化飞轮_vX.Y.Z.skill`；
2. 在 WorkBuddy 或其他宿主的 Skill 安装入口导入；
3. 回到对话说“开始设置”；
4. 按采访建立本地工作区并上传第一条材料。

不要让客户理解 GitHub、哈希、工作区 Schema 或机构运行时。安装说明、首次设置和反馈入口全部由 Skill 自己完成。

## 渠道职责

- **GitHub**：源码、Tag、Release、Issue 和贡献记录；
- **国内下载渠道**：原样转发正式 `.skill`，不产生自己的代码分支或包装包；
- **客户成功/服务人员**：帮助安装、收集反馈卡、去重和分级；
- **维护者**：把通用问题转成上游 Issue，修复、测试、发布下一版；
- **机构主管**：只审核本机构知识和运行时，不负责修改公共 Core。

## 反馈入口

客户只需要说：

```text
我要反馈问题。
我要提一个建议。
这个分析结果不太准，我要反馈。
```

Skill 读取本文件，用 `scripts/product_feedback.py` 生成脱敏反馈卡。默认只包含 Core 版本、宿主、问题分类、预期、实际和合成复现步骤，不读取或打包患者材料、机构名称、成员名单、完整日志、工作区路径或凭证。

反馈卡生成后交给向客户提供安装包的服务人员。Skill 不自动上传或发送反馈；以后接入快商通表单或工单系统时，也必须先展示发送范围并得到明确授权。

## 反馈分级

| 分类 | 进入哪里 | 优先级 |
| --- | --- | --- |
| 隐私泄漏、审核绕过、越权读取 | 私密安全通道 | P0 |
| 无法安装、无法启动、数据可能损坏 | 维护工单 | P0/P1 |
| 分析明显错误、路由错误、输出缺失 | 产品缺陷池 | P1/P2 |
| 新功能和体验建议 | 需求池 | P2/P3 |
| 某家机构自己的知识或流程 | 机构工作区 | 不进入公共 Core |

服务人员不得要求客户把真实患者截图、录音或聊天记录发到公共群、公开表单或 GitHub。确需复现时，优先创建完全合成案例；真实材料只能走机构批准的私密数据流程。
