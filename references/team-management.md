# 团队管理模块

团队管理不是给员工打分，而是把“沟通证据、咨询行为、训练动作、业务结果”放在同一张管理桌上，帮助主管每天完成一个最重要的管理动作，并在新样本中验证团队是否真正学会。

## 第一性原理

一个员工的结果不能只看最终数字。管理者要同时看三层：

```text
员工状态与沟通
→ 过程行为是否发生
→ 咨询结果是否改善
→ 下一轮应该教什么、支持什么、停止什么
```

三类资料必须分开保存，再按员工、周期、机构、科室/病种和渠道关联：

- **员工沟通记录**：一对一沟通录音、转写、员工自述、管理者观察、承诺事项和需要支持的障碍；
- **过程量数据**：有效线索、首响、有效咨询、留资、回访、预约和处理时效；
- **结果数据**：到院、爽约、付费、退款、投诉和其他机构定义的结果事件。

不要把员工沟通中的情绪、家庭或健康信息自动写入绩效结论。只提取与工作支持直接相关的事实，并允许员工或主管修正。

## 每日管理闭环

主管每天按以下顺序使用：

```text
开始今天的工作 → 处理P0/P1待办 → 生成一个晨会训练
→ 辅导重点员工 → 复查新样本 → 下班日清 → 次日复查
```

首页只突出一个团队断点。选择顺序是受影响员工数、独立样本数、证据质量；没有足够证据时明确显示“证据不足”，不为了填满页面制造结论。

## 工作区结构

第一版一个 Skill 只管理一个主管团队。前台只按成员放资料，日期和资料类型由 Skill 后台自动处理：

```text
08_团队管理/
├── 01_成员/A001_张三/
│   ├── 01_今天放这里/
│   ├── 02_历史资料/
│   └── 03_个人报告/
├── 02_团队会议/
│   ├── 01_今天放这里/
│   └── 02_会议报告/
├── 03_团队数据/01_今天放这里/
└── 04_团队报告/
```

用户每天只需要把录音、微信聊天或文件放到成员的 `01_今天放这里`；历史资料放到 `02_历史资料`。详细目录、命名规则和夜间循环读取 [team-file-conventions.md](team-file-conventions.md)。原始录音和未脱敏资料只能受控读取；私有团队报告可以显示员工姓名，发布包和对外材料必须去除员工姓名。

## 最小数据口径

首次使用不强迫用户理解字段。数据可以来自飞书文档、WPS、腾讯文档或本地 Excel。优先使用宿主提供的连接器；没有连接器时，把云文档导出为 CSV/XLSX/JSON 放入 `03_团队数据/01_今天放这里`，Skill 先提示需要转换或补充的最小信息。

建议每条过程/结果记录至少包含：

`date、employee_id、employee_name、institution、department、disease_or_project、channel`

以及以下数字字段（没有就留空，不得猜测）：

`valid_leads、first_responses、effective_consultations、contacts_obtained、followups、appointments、arrivals、paid_cases、refunds、complaints、process_minutes`

默认指标口径，可由机构修改并写入 `_系统/指标口径.json`：

- 咨询转化率：`appointments / effective_consultations`；
- 到院率：`arrivals / appointments`；
- 付费率：`paid_cases / arrivals`；
- 留资率：`contacts_obtained / valid_leads`。
- 有效咨询到院率：`arrivals / effective_consultations`；
- 每名咨询师有效到院数：周期内该员工的 `arrivals`；
- 训练动作采用率：采用动作的员工数 / 应训练员工数；
- 训练动作复查通过率：通过复查员工数 / 已采用员工数；
- 销冠动作团队复制率：稳定通过的非来源咨询师数 / 可复制的非来源咨询师数。

如果机构的“咨询转化率”口径不同，必须先确认口径再计算。分母为零、样本量过小或数据周期不完整时显示“无法判断”，不显示虚假的百分比。

## 周报工作流

管理者说“生成本周团队报告”时，按以下顺序执行：

1. 读取本周过程量和结果数据，检查周期、员工、科室、病种和渠道是否一致；
2. 按员工生成过程量、关键转化率、结果、数据缺口和变化趋势；
3. 受控读取该员工近一个月的一对一沟通记录，提取工作相关的状态、障碍、需要的资源和已承诺动作；不输出与工作无关的隐私；
4. 找出“过程量不足、过程动作不足、结果转化不足、结果好但风险高”中的主要类型；
5. 每名员工只给一个本周优先动作，并写明示范案例、练习方式、截止日期和复查样本；
6. 记录管理者和员工的反馈，下周用新数据复查，不自动改变员工档案或能力包。

周报先给三行结论：

```text
本周状态：……
最主要断点：……
本周只做一个动作：……
```

再提供证据表：数据周期、样本量、过程量、转化率、结果、沟通记录数量、风险和缺口。

不按预约数量简单排名，不把少量高质量线索与大量低质量线索直接比较，不把员工状态标签当作人事结论。

日报回答“今天处理什么”；周报回答“教了什么、谁学会了”；月报回答“哪些能力被复制、结果是否改善”。所有指标都必须带周期、分子、分母、来源和完整性状态。

## 月度一对一沟通

默认每月与每名员工做一次一对一沟通。沟通录音或纪要放入 `02_员工沟通记录/`，文件名建议包含：

`员工编号_YYYY-MM-DD_一对一沟通`

Skill 将近四周数据和本次沟通合成为“月度员工支持报告”，结构为：

1. 员工本月承担的范围和样本口径；
2. 过程量与结果变化；
3. 员工自述的困难和管理者观察；
4. 已验证的优势；
5. 只有一个最重要的改进点；
6. 管理者需要提供的资源或排障动作；
7. 员工确认的下月动作；
8. 下次复查日期与证据。

沟通报告是“支持和改进记录”，不是自动绩效定级。涉及人事、薪酬、奖惩或健康信息时，只提示由授权管理者按机构制度处理。

## 目标与“翻倍”模式

Skill 可以帮助机构设定“咨询转化翻倍目标”和“到院翻倍目标”，但必须把它当作目标和实验，不把目标当成已实现结果。

每个目标必须记录：

- 基线周期和基线样本量；
- 指标定义和分母；
- 目标周期；
- 目标值（默认基线 × 2）；
- 当前值、差距和置信程度；
- 使用了哪些 Skill 动作；
- 可能影响结果的外部因素；
- 复查日期和负责人。

当基线为零、样本量不足、数据口径变化或渠道/病种变化时，显示“暂不能判断翻倍”。除非经过机构真实对照试验，否则对外只能说“以翻倍为目标进行验证”，不能说“保证翻倍”。

## 输出安全边界

- 默认不生成员工自动排名、自动定级或人事结论；
- 不从员工沟通录音推断人格、心理疾病、家庭关系或忠诚度；
- 不把过程量多等同于能力强，不把结果差等同于态度差；
- 所有报告标注数据周期、样本量、来源和缺口；
- 任何涉及患者隐私、医疗判断、投诉或合规事件的内容只提供管理处置建议，必要时转授权负责人；
- 只有管理者明确要求时才读取原始沟通录音，普通员工视图只显示与本人工作相关的摘要和行动。
