# 初始化与团队蒸馏流程

面向用户的双入口操作和逐步提示词见 [initialization-and-distillation-prompts.md](initialization-and-distillation-prompts.md)。本文件保留蒸馏规则和状态闸门；用户不需要理解内部模块名。

## 初始化状态

使用以下状态帮助管理者理解进度：

`未初始化 → 资料整理中 → 已建立机构档案 → 首轮蒸馏中 → 影子运行 → 可持续迭代`

不要把技术状态直接展示给学员；用“资料准备”“能力生成”“待确认”“已可以使用”等自然语言表达。

## 资料接入

支持文档、PDF、表格、录音、微信 HTML、聊天截图和长图。按以下顺序处理：

1. 保留原文件和原路径；
2. 判断文件类型和是否含敏感信息；
3. 对录音转写并保留时间点；
4. 对长图切片、OCR，并保留原图位置；
5. 从文档、OCR 和转写中提取机构事实、案例和待确认项；
6. 生成资料准备报告，不因解析失败而丢弃原始材料。

## 案例准备

不要求管理者预先整理目录。先自动建议标签，再让管理者确认：

- 科室、病种或项目；
- 来源渠道；
- 优秀、普通、失败、未预约、爽约或回访；
- 是否有真实结果；
- 是否可以用于团队学习；
- 是否完成脱敏与授权。

上传量不足时先建立试运行版本。推荐逐步达到 30 条以上可比案例；如果有条件，使用 50～80 条包含成功与失败对照的案例。

## 候选规则卡

每条候选规则至少包含：

- 规则名称；
- 适用阶段和场景；
- 观察到的行为；
- 支持证据；
- 反例或限制；
- 适用渠道和科室；
- 置信度；
- 合规状态；
- 管理者决定；
- 目标版本。

没有证据、没有边界或只有单个成功案例时，标记为“待验证”，不得进入已发布能力包。

## 发布与升级

首次发布采用影子运行：只输出分析、建议和待确认项，不用于自动绩效处理。每轮升级都执行：

1. 汇总新案例和管理者反馈；
2. 生成候选规则；
3. 审核事实与安全边界；
4. 用固定案例测试新旧版本；
5. 发布新版本并保留旧版本；
6. 记录变更原因和可回滚点。
