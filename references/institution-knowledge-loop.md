# 机构知识同步蒸馏

## 核心定义

每轮录音、微信、私信、文档和 OCR 处理都同时产出两类候选：

```text
咨询能力候选
→ 销冠判断、阶段动作、顾虑处理、陪练和团队规则

机构知识候选
→ 机构介绍、科室项目、服务流程、医生信息、优势资质和案例素材
```

两者不能混为一层。前者回答“应该怎么咨询”，后者回答“这家机构真实有什么”。

## 机构知识目录

用户可把资料放在以下入口；旧资料不需要搬动，Skill 会建立索引：

```text
咨询转化工作区/
├── 01_机构介绍/
├── 02_科室项目与服务/
├── 03_咨询流程与标准/
├── 04_优秀咨询案例/
├── 05_普通失败与未预约案例/
├── 06_团队培训与反馈/
├── 07_我的产出/
├── 08_团队管理/
└── _系统/
    ├── 当前机构知识/
    │   ├── active.json
    │   └── versions/
    └── 机构知识候选/
```

## 六类知识

1. 机构介绍：定位、服务范围、地址和对外介绍；
2. 科室项目与服务：病种、项目、服务内容、流程和适用场景；
3. 医生与团队：医生擅长方向、职称、出诊和服务特点；
4. 优势与资质：设备、技术、认证、奖项、环境和保障；
5. 案例与证明素材：脱敏案例、患者问题、过程和已确认结果；
6. 咨询表达资产：销冠如何介绍机构、项目、医生和案例。

## 证据规则

录音中的机构说法只能是知识候选，不自动等同于机构事实。每条知识至少记录：

```text
知识 ID、知识域、名称、内容、机构/科室/病种范围
来源文件、录音时间点或聊天位置、来源类型
首次发现时间、最近确认时间、生效/失效时间
审核状态、可信度、冲突信息和适用限制
```

来源优先级建议为：已审核机构资料 > 已确认知识库 > 管理者明确确认 > 多条一致咨询记录 > 单条咨询记录。

## 状态与运行规则

- `approved/confirmed`：可以进入运行时回答；
- `pending_review`：已提取但只能供管理者审核；
- `conflict`：与现有知识冲突，不能直接引用；
- `deprecated`：过期或已撤销，不能引用；
- `rejected`：不合规、无法验证或涉及隐私。

价格、医生、地址、活动、资质、疗效、周期和案例结果默认属于高风险知识，未经管理者确认不能进入团队发布包。原始患者姓名、电话、微信、病历和头像不能进入机构知识包。

## 每轮 Dream Cycle

```text
全量/增量扫描
→ 转写、OCR、HTML 解析和脱敏
→ 生成咨询能力候选 + 机构知识候选
→ 去重、实体归并、时间检查
→ 发现冲突和过期信息
→ 管理者确认
→ 分别写入能力包和机构知识包
→ 运行时同时加载
→ 团队发布包只携带已确认知识
```

每轮报告必须说明：新增知识、待确认知识、冲突知识、过期知识、被拒绝知识及其证据位置。
