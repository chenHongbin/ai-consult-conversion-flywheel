# 首次全量接管与后续增量飞轮

## 核心规则

`第一次蒸馏 = 全量扫描当前工作空间 + 全量处理候选资料`；
`后续蒸馏 = 只处理新增或发生变化的资料`；
`分析这一条 = 只有用户明确指定单条时才使用的单案例模式`。

用户不需要先整理目录，也不需要理解索引、哈希和覆盖率。Skill 在后台建立资料清单，原始文件只读、不移动、不改名、不删除。

“全量”指所有符合咨询转化资料类型的内容都进入处理队列，不是把所有文件一次性塞进一个提示词。资料先逐条转写、OCR、解析和标准化，再按批次汇总蒸馏。

## 首次蒸馏状态机

```text
未初始化 → 首次全量扫描 → 资料索引完成 → 转写/OCR/文档提取
→ 覆盖率闸门 → 案例标准化 → 销冠全链路蒸馏
→ 候选能力包 → 固定测试 → 影子运行
```

用户第一次说“蒸馏销冠”“蒸馏这一批”“更新咨询能力”时，必须执行首次全量模式。即使当前只有一条 `.txt`，也要先扫描工作空间中的所有录音、聊天记录、截图、长图、HTML、文档和表格，再处理所有可用候选资料。

扫描范围是用户当前选择的工作空间根目录，而不是 Skill 安装目录或某个预设子文件夹。自动排除 `_系统`、处理输出、缓存、Git 和临时文件；`咨询转化工作区/01-06` 与 `08_团队管理` 的原始资料仍然纳入扫描。

IMA 路径使用当前用户明确授权且可访问的知识库作为资料源，自动枚举其可读内容；不能把历史示例知识库当作默认资料。

## 多阶段处理

1. 建立 `workspace-inventory.jsonl`，以文件哈希识别新增、变化、重复和未变化资料；
2. 录音调用 YouNavi 批量转写；
3. 长图切片后 OCR；微信 HTML 保留消息顺序；文档和表格进入文档提取队列；
4. 为每条材料建立案例卡，记录证据位置、结果来源、授权、脱敏和质量；
5. 先做分批案例卡，再按正向参考、反向参考、普通/对照、结果未知和方法参考分层对照；
6. 同时提取机构介绍、科室项目、服务、医生、优势、资质和脱敏案例，生成机构知识候选；
7. 最后提炼销冠完整销售逻辑、顾虑专项、100 问、200 问和陪练场景；
8. 用固定测试集验证后，分别发布咨询能力候选和机构知识候选；机构知识首轮采用待确认/影子运行。

不要把所有原始文本一次性放入模型上下文，也不要因为一条已有转写就跳过其余音频。

## 覆盖率闸门

每次全量处理都必须生成覆盖率报告，至少显示：发现总量、录音数量、已有转写、待转写、图片数量、待 OCR、文档待提取、失败、重复、可标准化数量和新增/未变化数量。

当仍有待处理资料时，状态只能是“部分完成”，产物只能叫“部分样本候选分析”。不得命名或宣称为“完整销冠能力包”。只有所有候选资料已处理，或被明确记录为失败、排除、重复或待授权，才允许进入“可蒸馏”状态。结果未知不属于排除条件，仍应进入候选分析。

单条失败不阻塞其他资料，但必须留在失败清单中；IMA 权限或限频错误应暂停该资料源，并继续处理本地资料。

## 后续增量

全量处理完成后，状态记录为 `processing_complete`。下一次运行自动比较文件哈希：新文件和内容变化文件进入队列，未变化文件跳过。新增结论先进入候选更新区，经过对照、合规检查和固定测试后再升级能力包版本；机构知识还必须经过事实确认、冲突检查和有效期检查。

## 推荐后台脚本

```bash
python3 scripts/inventory_workspace.py <工作空间根目录>
python3 scripts/run_full_distillation.py <工作空间根目录> --run-transcription --run-ocr
```

第二条命令负责资料处理和闸门，不代替 Agent 做最终语言模型蒸馏。闸门通过后，Agent 才能读取案例清单，按 [champion-full-funnel-distillation.md](champion-full-funnel-distillation.md) 执行多阶段汇总。
