# 销冠全链路蒸馏主干与顾虑专项模块

## 不变的核心原则

AI咨询转化飞轮蒸馏的第一产物，永远是：

> **本机构、本科室、本病种/项目、本渠道下，优秀咨询师完整的销售逻辑、判断过程和销售流程。**

客户顾虑、流失节点、客户常见 100 问、新人必知必会 200 问，都是从销冠全链路上切出来的专项模块，不能替代全链路蒸馏。

不能把“销冠话术”理解成金句集合，也不能把“成交结果好”直接等同于“每一句话都正确”。真正需要复制的是：

```text
客户处于什么阶段
→ 咨询师观察到什么信号
→ 咨询师做了什么判断
→ 采取了什么动作
→ 为什么在这个时机推进
→ 客户发生了什么变化
→ 下一步如何承接
```

## 销冠完整销售逻辑

根据具体机构和渠道调整名称，但原则上必须覆盖完整链路：

```text
线索进入
→ 破冰与首响
→ 识别来源与初步问题
→ 获取微信/电话等联系方式
→ 深挖需求、现状和决策人
→ 判断阶段与真实顾虑
→ 解释匹配价值与服务边界
→ 处理费用、效果、信任等顾虑
→ 邀约到院
→ 到院前确认与降低爽约风险
→ 到院承接与医生/服务转交
→ 未成交回访
→ 爽约、未到院和长期培育
```

任何单条资料没有覆盖某一环时，标记“证据缺失”，不能假设销冠在这一环节的做法。整批资料可以通过不同性质的材料互补：患者咨询证明真实互动，内训/策略资料补充明确方法，但两者不能混为同一种证据。

## 全量样本纳入与证据权重

首次蒸馏必须把工作空间中所有可读的录音转写、微信/私信文本、截图 OCR、会议/内训转写和相关文档列入清单。不要要求用户先把资料整理成“已到院/未到院”。

每条资料先标注四个字段：

| 字段 | 可选值 | 用途 |
|---|---|---|
| `source_nature` | 患者咨询、团队内训/策略、方法模板、未知 | 决定可以提炼什么 |
| `sample_role` | 正向参考、反向参考、普通/对照、未知案例、方法参考 | 决定放入哪组对照 |
| `outcome_provenance` | 对话明确、机构数据、路径/文件名标签、未提供 | 判断结果可信度 |
| `sample_weight` | 高、中、低、仅上下文 | 控制样本是否被作为正向/反向参考 |
| `result_weight` | 高、中、低、仅上下文 | 控制结果标签对汇总的影响 |

建议权重：优秀/红板、失败/黑板等明确样本筛选信号可设为高；普通/对照为中；未知为低。结果权重则以实际对话或机构数据为高、只有文件夹或文件名标签为中、没有结果为低；内训/方法资料为“仅上下文”。权重只影响汇总，不允许过滤样本。

“到院”不是质量证明，“未到院”也不是错误证明。必须回到八步法，检查阶段、顾虑、动作、证据、客户反应和安全边界。未知结果样本仍用于发现流程、顾虑和表达模式，但结论标为候选。

## 双层蒸馏结构

### 第一层：销冠全链路主干

必须先形成：

- 销冠销售流程图；
- 每个阶段的进入信号和退出条件；
- 每个阶段的判断问题；
- 每个阶段的关键动作；
- 阶段之间的推进逻辑；
- 常见断点和补救动作；
- 电话、微信、私信等渠道差异；
- 科室/病种差异；
- 不能复制的个人风格；
- 机构必须确认的事实和合规边界。

### 第二层：痛点专项模块

沿着全链路挂载：

- 流失节点诊断；
- 费用与价值顾虑；
- 效果与既往失败顾虑；
- 医院、医生与案例信任顾虑；
- 距离、时间和家人意见；
- 预约、爽约、未到院和回访；
- 100 个客户高频问题；
- 200 个新人必知必会问题；
- 针对每个痛点的 AI 陪练场景。

如果专项模块和销冠全链路结论冲突，以有证据的全链路判断为主，并将冲突交给管理者审核。

## 全链路蒸馏提示词

```text
请不要只提炼销冠金句。请先读取本批所有样本及其 `source_nature`、`sample_role`、`result_weight` 和 `outcome_provenance`，再蒸馏完整的销售逻辑和销售流程。任何可读样本都要分析，不因没有“已到/未到”标签而跳过。

请按以下链路逐段分析：线索进入、破冰首响、获取联系方式、深挖需求、阶段判断、真实顾虑、价值解释、顾虑处理、邀约到院、到院前确认、到院承接、未成交回访、爽约与长期培育。

对每个阶段输出：
1. 客户处于这一阶段时会出现什么信号；
2. 销冠会观察什么；
3. 销冠做了什么判断；
4. 销冠采取了什么动作；
5. 为什么在这个时机做；
6. 下一阶段的进入条件是什么；
7. 正向、反向、普通/对照和未知案例分别在哪个环节推进或断掉；
8. 哪些内容来自患者真实互动，哪些来自内训/策略方法参考；
9. 哪些内容是机构事实，哪些只是行为规律；
10. 哪些做法不能外推或必须转人工/医生。

最终输出“销冠完整销售逻辑图”和“阶段动作卡”，不要生成脱离上下文的金句合集。内训/策略资料另出“方法参考卡”，不能写成患者结果证据。
```

## 顾虑专项蒸馏提示词

```text
在完成销冠全链路蒸馏后，请沿着每个阶段提取客户顾虑和流失节点。

优先检查：
1. 费用贵、担心乱收费、不知道值不值；
2. 担心效果、过去治疗失败；
3. 不信任医院、医生或案例；
4. 距离远、时间少、家人不同意；
5. 预约后犹豫、爽约、未到院和回访失联。

不要只统计顾虑出现次数。请说明每种顾虑出现在哪个阶段、客户真正担心什么、销冠如何判断、如何回应、回应后客户是否进入下一阶段，以及普通/失败案例的不同。
```

## 100 个客户问题的正确产物

100 个问题应当是“客户问题意图”，不是把同一个问题改写成 100 种句子。每张卡包括：

```text
客户问题意图
常见表达
出现阶段
表面问题
真实顾虑
适用渠道和病种
销冠回应逻辑
已审核证据
标准回应结构
可替换表达
不应该说什么
下一步动作
支持案例与反例
置信度和待确认项
```

“标准答复”必须是可审核的回应结构，不是脱离条件的固定承诺。没有机构事实时，只生成变量和待确认项。

## 200 个新人问题的正确产物

200 个问题是训练题库，不是让新人一次背完的答案库。每题至少包含：场景和客户原话、新人需要先判断什么、合格回应结构、常见错误、禁止表达、评分标准、是否需要转主管/医生、对应的销冠行为卡和可进入 AI 陪练的变化场景。

训练时分为“知道 → 模仿 → 变式 → 真实复盘”四层，不以背诵固定话术作为通过标准。

## 证据与晋升规则

一条销冠行为或标准回应要进入机构能力包，至少满足：

1. 两条以上可比案例支持；
2. 至少一个适用条件；
3. 至少一个反例或限制；
4. 机构事实已确认；
5. 医疗安全边界已检查；
6. 固定测试集通过；
7. 管理者审核后进入影子运行。

一个成功案例只能形成候选假设，不能直接成为标准流程。
