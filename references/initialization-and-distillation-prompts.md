# AI咨询转化飞轮：设置完成后的咨询销冠蒸馏操作手册

> 本文件不控制“开始设置”，首次五问不得读取本文件来决定问题或顺序。首次设置只使用 `v2.1.1-onboarding-runtime.md`；本地文件夹和 IMA 是设置完成后的资料接入方式，不得在第一轮询问。

## 先理解两种资料

AI咨询转化飞轮处理两类不同证据：

1. **机构知识**：机构、科室、病种/项目、医生、地址、价格、流程、渠道和合规边界。它回答“这家机构有什么、能说什么”。
2. **咨询案例与方法资料**：优秀、普通、失败、未预约、到院、未到院、结果未知的录音/微信记录，以及团队内训、会议和策略资料。它们分别回答“团队怎么做”“哪些动作可能有效”“哪些方法被明确教过”，不能混成一类证据。

两者不能混成一层。没有机构知识库时，可以先蒸馏咨询行为，但不能生成未经确认的价格、医生信息、疗效、治疗周期或机构流程。

## 路径一：当前工作空间里已经有资料

### 用户操作

1. 在当前工作空间安装 AI咨询转化飞轮；
2. Skill 自动对当前工作空间做只读盘点，不要求用户先整理资料；
3. 第一次说“蒸馏销冠”时，自动处理所有候选录音、聊天记录、截图、HTML、文档和表格；
4. Skill 记录机构、科室、资料源和授权范围，缺失项进入待补充清单；
5. 只有用户明确说“分析这一条”时，才执行单案例分析。

### 推荐提示词 1：扫描当前空间

```text
第一次使用 AI咨询转化飞轮。请先扫描当前工作空间，盘点已有的文档、PDF、表格、录音、微信 HTML、聊天截图和长图。

不要移动、改名、上传或删除原文件。先输出：
1. 资料数量、类型、大小和日期范围；
2. 可能是机构知识、咨询案例、团队培训、员工管理和无关资料的目录；
3. 哪些目录可能包含敏感信息；
4. 哪些资料适合先处理；
5. 缺少哪些关键确认；
6. 后续需要转写、OCR、文档提取的资料数量。

原文件必须保持不变。扫描完成后自动在当前工作空间建立或使用 `咨询转化工作区/` 作为后台入口，不要求用户搬运旧资料。
``` 

### 工作区边界

当前选择的工作空间根目录就是首次全量扫描边界。Skill 在当前根目录建立编号文件夹，并把旧资料建立只读索引，不自动搬动旧文件。内部等价于：

```text
python3 scripts/init_consult_workspace.py 当前工作空间 --use-root
```

如果当前目录混有多个项目或私人文件，Skill 仍然先扫描，但会把无咨询信号的支持文件标记为“其他可识别文件”，不自动进入蒸馏；原有资料不动。用户无需自己逐个分类。

### 设置完成后补充机构资料

```text
我的首次设置已经完成，请补充机构资料来源。

机构名称：〔填写〕
当前科室：〔填写〕
主要病种/项目：〔填写；不知道就写待确认〕
资料来源：〔本地文件夹 / IMA / 两种都用〕
是否允许用于团队学习：是 / 否 / 部分资料允许

请更新资料入口，不要重新进行角色、机构、团队的首次采访，也不要编造任何医生、价格、地址、疗效、治疗周期或流程信息。
初始化完成后告诉我：哪些事实已确认、哪些待补充、下一步只需要我提供哪三类资料。
```

### 推荐提示词 3：有 IMA 知识库

```text
请使用我指定的 IMA 知识库初始化 AI咨询转化飞轮。

先列出当前账号可访问的知识库和简介，不要根据历史示例猜测，也不要自动选择。
我选择：〔知识库名称〕
用途：初始化〔机构/科室/病种或项目〕的咨询转化能力
允许读取范围：〔文件夹或目录〕

读取前请记录来源、用途和授权范围；读取后输出机构事实清单、缺失事实清单和资料质量报告。不要把 IMA 内容写进 Skill 源码或通用知识库。
```

### 推荐提示词 4：首次全量蒸馏

```text
请执行 AI咨询转化飞轮的“首次全量蒸馏”。
请递归扫描当前工作空间根目录内所有候选录音、微信聊天、聊天截图、长图、HTML、文档和表格，不要只读取已经转写好的文本。
先建立资料清单，再批量执行：已有转写匹配 → YouNavi 转写 → 长图切片 OCR → HTML/文档解析 → 脱敏 → 案例标准化 → 覆盖率报告。
覆盖率未达到完整前，不要生成“完整销冠能力包”，只能生成“部分样本候选分析”。
全部可用资料处理完成后，再按销冠完整销售逻辑、优秀/普通/失败对照、顾虑专项、100问、200问和固定测试执行蒸馏。
机构〔〕、科室〔〕、病种/项目〔〕、渠道〔〕未知的内容标记待确认，不要猜测。
```

### 推荐提示词 5：明确单条分析

```text
只分析我指定的这一条咨询，不要扫描或蒸馏其他资料。
绑定上下文：机构〔〕、科室〔〕、病种/项目〔〕、渠道〔〕。
先输出资料是否可读、是否脱敏、说话人和时间点是否可靠；再按咨询转化八步法生成一张咨询复盘卡。
不要把这一个案例直接变成团队规则或发布能力包。
```

## 路径二：只有大量录音，没有机构知识库

这条路径允许直接开始，但产物名称必须是**临时咨询能力包**，不是完整机构 Skill。它只能学习咨询师的行为模式、提问顺序、顾虑处理和推进动作；涉及机构事实的内容全部标记为“待机构确认”。

### 最小建议

- 10～20 条：跑通流程，发现资料质量问题；
- 30 条以上：形成初步行为规律；
- 50～80 条：优秀、普通/失败、结果对照较完整，可形成首轮候选能力包；
- 最好同时包含优秀和非优秀案例，不能只给销冠成功录音。

### 推荐提示词 6：无知识库启动蒸馏

```text
我现在没有机构知识库，但有一批咨询录音，想先蒸馏咨询销冠。

请先把当前工作空间中的全部候选录音和聊天资料当作“待整理案例”，不要只读取已经转写好的那一条，也不要直接下结论或编造机构事实。
第一轮扫描整个工作空间，输出数量、格式、时长、重复文件、转写可行性、说话人可识别度、可能的科室/病种/渠道、结果标签缺口和隐私风险盘点；然后自动批量转写和标准化。

请告诉我还需要补充哪些最小信息，并把最终产物定义为“临时咨询能力包 v0.1”。同时可以提取机构/科室/医生/项目的知识候选，但这些内容全部标记“待机构确认”，不能用于机构价格、医生、地址、疗效、治疗周期和医疗建议。
```

## 咨询销冠蒸馏的标准步骤

### 第 1 步：资料盘点与全量/增量登记

```text
请扫描当前工作空间根目录并生成批量处理清单。第一次运行必须覆盖所有候选资料；之后根据文件哈希只处理新增或变化资料。保留原文件路径和哈希，不移动、不删除。
请区分录音、转写、微信 HTML、聊天截图、长图、教学示例和无关资料；标记重复、损坏、未完成上传和疑似敏感资料。
输出待确认字段：咨询师、科室/病种、渠道、日期、结果、是否优秀、是否允许团队学习。
```

### 第 2 步：转写、切图与标准化

```text
请处理清单中的全部候选案例：录音优先调用 YouNavi 批量转写，长图先切片再 OCR，微信 HTML 保留消息顺序。不要因为已经有一条 TXT 就跳过其他录音。
保留说话人、时间点、原文件路径和图片切片位置；对姓名、电话、微信号、病历号和头像做脱敏并标记人工复核。
转写不可靠或 OCR 不完整的案例不要进入高置信度蒸馏，只放入待复核区。
```

### 第 3 步：案例标签与结果分层

```text
请为每条材料建立标准标签：机构、科室、病种/项目、渠道、咨询师、咨询阶段、患者主要顾虑、是否留资、是否预约、是否到院、是否成交、是否回访、结果来源、授权状态、`source_nature`、`sample_role`、`analysis_route`、`sample_weight` 和 `result_weight`。
所有可读材料都纳入分析。将患者咨询分为正向参考、反向参考、普通/对照和结果未知；将内训/会议/策略资料标为方法参考；将非患者商务沟通标为非目标样本。结果未知不要猜，但不能跳过。
```

### 第 4 步：单条案例深度分析

默认使用咨询转化八步法，按“八步阶段 → SPIN/LEARN/FABE → 45 节奏 → 医疗安全 → 下一步动作”分析。结果标签只作为权重，不能替代逐轮证据。

```text
请按 AI咨询转化飞轮的默认咨询复盘标准分析这条案例：
1. 当前处于哪个咨询阶段；
2. 患者显性问题和隐性顾虑是什么；
3. 咨询师做了哪些关键动作，按时间点引用证据；
4. 哪个动作推动了下一步，哪个动作造成了断点；
5. 是否存在事实错误、过度承诺或医疗风险；
6. 下一轮只优先练哪一个动作。
请区分“录音中明确出现的事实”和“基于方法论的推测”，不要把单条案例直接升级为规则。
```

### 第 5 步：优秀与普通/失败对照

```text
请将优秀案例与同科室、同病种、同渠道的普通/失败案例做对照。
不要只摘录话术，请比较：进入阶段、提问顺序、倾听比例、顾虑识别、回应方式、推进时机、留资/邀约动作、回访动作和医疗边界。
每个差异写成“在什么条件下，咨询师做了什么，出现了什么结果”；同时列出反例和不能外推的情况。
```

### 第 6 步：生成销冠行为卡

```text
请基于至少两条支持案例和一个边界/反例，生成咨询销冠行为卡。
每张卡包含：行为名称、适用阶段、触发条件、具体动作、可用表达结构、禁止做法、支持案例、反例、适用渠道/病种、证据强度、待机构确认项。
不要把某位销冠的个人风格直接写成所有人必须照抄的话术；优先提炼可训练的判断和动作。
```

### 第 7 步：机构事实补齐与知识绑定

```text
请把本轮蒸馏得到的内容分成两类，并分别输出：
A. 可迁移的咨询行为规律；
B. 必须由机构确认的事实。

B 类请整理为 `_系统/机构知识候选/本轮/knowledge-candidate.json`，至少覆盖：机构介绍、科室项目与服务、医生与团队、科室优势与资质、脱敏案例和咨询表达资产。每条知识必须带 `id`、`domain`、`name`、`claim`、`evidence_refs`、`source_type`、`review_status` 和生效/失效时间（未知则写待确认）。
请区分：已审核机构资料、管理者确认、多人重复提及、单条录音说法和患者转述。单条录音说法只能成为候选，不能自动进入运行时知识。

对 B 类列出最小补充清单：机构名称、科室、病种/项目、医生、服务边界、地址、价格、预约流程、渠道规则和合规禁语。
没有资料的地方统一写“待机构确认”，不要根据录音猜测或补写。
```

### 第 8 步：固定测试与影子运行

```text
请用未参与本轮蒸馏的固定案例测试临时咨询能力包。
至少评估：阶段判断、顾虑识别、关键动作识别、下一步建议、医疗安全和是否过度外推。
输出新旧版本差异、错误案例、无法判断案例和需要管理者审核的规则。
先进入影子运行，只用于复盘和陪练，不自动用于绩效、不自动发布、不自动替代医生判断。
```

### 第 9 步：发布机构专属能力包

```text
请生成“〔机构〕-〔科室〕-咨询转化能力包 v0.1”候选版。
能力包必须包含：适用范围、已确认机构事实、销冠行为卡、普通/失败反例、咨询阶段动作、合规边界、未知项、证据索引、固定测试结果和版本变更记录。
将所有未经确认的价格、医生、地址、疗效、周期和流程放入待确认区，不进入可执行规则。
请先给我审核清单，不要自动发布。
```

如果覆盖率、证据、反例、隐私、医疗边界和固定测试全部通过，Agent 将候选写入当前工作空间，而不是修改公共 Skill：

```text
请把本轮咨询能力蒸馏结果整理为 `_系统/蒸馏候选/本轮/candidate.json`，把机构知识结果整理为 `_系统/机构知识候选/本轮/knowledge-candidate.json`。
然后分别运行：
`scripts/commit_capability_candidate.py <工作空间根目录> <candidate.json> --publish`
`scripts/commit_knowledge_candidate.py <工作空间根目录> <knowledge-candidate.json> --publish`
机构知识候选即使写入版本，也只有管理者确认的条目会进入运行时；发布后读取 `scripts/load_active_capability.py <工作空间根目录> --format markdown`，确认咨询能力和机构知识都已加载。
```

### 第 10 步：持续迭代

```text
请处理本周新增的优秀、普通和失败案例，只分析增量和发生变化的案例。
对照当前能力包，判断哪些行为被重复验证、哪些规则出现反例、哪些机构事实发生变化、哪些训练动作需要升级。
生成 v0.2 候选变更、证据列表、固定测试结果和回滚说明；不要覆盖当前版本，也不要自动发布。
```

候选确认后，使用 `scripts/commit_capability_candidate.py` 写入新版本；如果新版本表现变差，使用 `scripts/rollback_capability.py <工作空间根目录> --previous` 恢复上一版。

## 有知识库和无知识库的区别

| 项目 | 有机构知识库 | 没有机构知识库 |
|---|---|---|
| 第一产物 | 机构专属能力包候选版 | 临时咨询能力包 |
| 可分析内容 | 行为 + 机构事实 + 合规边界 | 主要是行为，事实全部待确认 |
| 录音要求 | 5～10 条可先跑通，30 条以上更稳定 | 先用 10～20 条检查质量，30～80 条再形成规律 |
| 价格/医生/地址 | 只引用已审核知识库 | 禁止猜测，统一待确认 |
| 能否生成机构话术 | 可以生成审核草稿 | 只能生成结构模板和变量 |
| 发布方式 | 影子运行后候选发布 | 补齐机构事实后再升级 |
| 下一步 | 补充反例、数据和团队反馈 | 建立机构档案，再绑定科室/病种/渠道 |

## 最简单的用户记忆版

```text
第一次：先扫描，不要急着蒸馏。
有机构资料：先初始化，再蒸馏案例。
只有录音：先蒸馏行为，所有机构事实待确认。
每轮结束：先测试、再审核、后发布。
```
