# v0.7：后台个人档案归档与夜间队列接通

## 这一版解决什么

用户继续只需要把资料放进“今天放这里”。Skill 在文件稳定后自动完成：

1. 识别员工、会议或团队数据；
2. 根据文件名日期，或文件修改时间，确定资料日期；
3. 保留用户前台原文件，同时复制到后台历史档案；
4. 统一后台文件名，记录员工编号、资料类型和哈希；
5. 将后台副本送入夜间分析队列，避免同一文件重复蒸馏。

## 后台目录

```text
_系统/
├── 团队档案/员工编号_姓名/YYYY/MM/YYYY-MM-DD/资料类型/
├── 团队会议/YYYY/MM/YYYY-MM-DD/会议类型/
├── 团队数据/YYYY/MM/YYYY-MM-DD/
└── 团队自动化/
    ├── 01_待处理队列/
    └── 02_运行日志/
```

`archive_team_inbox.py` 只复制，不移动、不删除原文件。它使用 `团队档案/归档索引.json` 做增量去重，并记录日期是来自文件名还是文件系统修改时间。默认等待 30 分钟，避免把仍在上传的录音或长图提前处理；补跑时可使用 `--force`。

## 夜间流程

`run_nightly_cycle.py` 每次先调用归档器，再把新归档副本加入队列：

```text
今天放这里
  → 稳定性检查
  → 后台个人/会议/数据档案
  → 哈希去重
  → 夜间任务 JSONL
  → YouNavi 转写 / 长图切片 OCR / 微信解析 / 数据校验
  → 管理者报告
```

同一天重复触发时，队列按 `task_id` 合并，不会因为本次没有新文件而覆盖之前尚未执行的任务。

前台文件路径仍可用于用户查找；队列优先引用后台归档副本，同时保留 `original_source`，确保每条分析都能回溯到用户最初放入的位置。

## 边界

- 第一版仍只支持一个主管团队；
- 不自动修改或删除原始资料；
- 不自动发布 Skill 能力包；
- 不自动绩效定级或写回外部系统；
- 不把原始团队资料打包进 Skill 发布包；
- 后台归档保存的是机构私有工作区数据，不能上传为通用模板。
