# V2.1 每日复盘数据与队列合同

## 对象层级

1. `artifact`：一张截图、一段录音或一个文本文件；
2. `conversation`：一次连续微信沟通或一通电话；
3. `patient_case`：经主管确认属于同一患者的一个或多个对话；
4. `consultant_day`：某员工某天的全部案例；
5. `team_day`：某团队某天的全部员工；
6. `learning_chain`：断点、训练动作和后续真实案例复查。

稳定 ID 为 `artifact_id`、`conversation_id`、`patient_case_id`、`consultant_day_id`、`team_day_id`、`analysis_task_id`、`training_action_id` 和 `learning_chain_id`。报告、任务和证据必须携带对应 ID。

幂等键以“员工作用域 + 来源哈希 + 分析合同版本”为核心，同一材料换路径或跨日重复提交不会生成第二份逐案报告；同一文件错误地分配给不同员工时仍保持两个独立员工作用域，等待主管处理。

## 患者归并

状态固定为：

`ungrouped → suggested → confirmed/rejected`

系统只能根据同一患者子文件夹或明确内部患者编号提出建议。相似姓名、病种、城市或说话方式不得自动合并。未经主管确认，每个对话使用独立 `patient_case_id`，不阻塞单案分析。

主管确认后，系统除统一 `patient_case_id` 外，还要建立一个 `patient_case_bundle_analysis` 任务，对该患者的微信、电话等全部已确认对话生成跨渠道组合报告。后续新增同患者材料时创建新的组合报告修订版；员工和团队统计仍只把该患者计算为一个独立案例。

## 任务状态

状态固定为：

`prepared → claimed → completed/failed/quarantined`

`claimed` 租约到期后可以重新领取。默认每批 20 条、租约 30 分钟、最多 3 次执行机会（首次加两次重试）。失败必须可见，不能因为单条失败阻塞其余任务。已完成任务不得重复生成报告。

## 存储

```text
_系统/每日复盘/
├── tasks/                 当前任务投影
├── leases/                领取租约
├── cases/<日期>/          结构化分析与内部报告
├── grouping/              患者归并人工决定
├── projections/           员工日和团队日投影
└── events.jsonl           追加式事件
```

原始材料不移动、不删除。事件只追加；当前状态可以由事件和报告重建。

Agent 领取任务时只得到最小 `context_pack`：当前案例作用域、逐案合同、八步法与安全规则、当前生效机构能力/知识路径、该员工唯一训练动作。不得默认加载其他员工原始材料或整套团队历史。

## 证据门槛

- 员工稳定长板或重复短板：至少 3 个独立患者案例，且覆盖相关案例的 50% 以上；不足时只标记“当日观察”。
- 团队共同断点：至少跨 2 名员工、3 个独立患者案例；P0 风险不受此门槛限制。
- 每名员工默认只保留一个进行中训练动作。
- 训练行为在 1 个新匹配案例中出现标记“已出现”；在至少 2 个独立新患者案例中重复出现标记“已稳定”。

## V2.1 结果边界

预约、到院、付款、退款字段可以预留，但值统一为 `unknown/missing`。行为改善不能等同于转化改善；真实结果接入和因果验证属于 V2.2。
