# 开源母体与本地运行时契约

AI咨询转化飞轮只有一个官方公共母体。任何机构安装同一份 Core，再在自己的工作目录中生成相互隔离的私有工作区。

## 四层模型

| 层级 | 内容 | 更新责任 | 是否进入上游仓库 |
| --- | --- | --- | --- |
| Public Core | 通用方法、路由、脚本、Schema、安全规则 | 项目维护者 | 是 |
| Organization Workspace | 机构资料、成员、患者材料、任务和审核账本 | 当前机构 | 否 |
| Organization Runtime | 已审核机构事实、团队动作、患者群体洞察和内容资产 | 当前机构主管 | 否 |
| Personal Overlay | 个人案例、训练和经验证的个人经验 | 当前咨询师 | 否 |

## 不变量

1. 一个工作区只绑定一个机构；不得在原工作区内改名实现机构切换。
2. Core 更新只能替换 Skill 文件，不得扫描、移动、覆盖或删除用户工作区。
3. 工作区升级必须由显式迁移脚本完成；打开新版 Core 不等于同意迁移数据。
4. 机构运行时发布是本地审核动作，不是 GitHub 项目发版。
5. 离线团队包只是可选导出。默认使用方式是安装公共 Core，并从本地工作区加载机构运行时。
6. 回到上游的贡献只能包含通用代码、文档、合成测试和脱敏规则，不得包含真实患者或机构资料。
7. 默认不上传遥测、案例、日志或使用结果。任何联网、外发或共享都需要用户对具体范围重新授权。

## 版本轴

- `Core 2.x`：GitHub 公共项目和官方安装包版本，读取根目录 `VERSION`。
- `Workspace Schema v2.1.3`：本地目录与数据契约版本，独立于 Core 演进。
- `Organization Release`：某一工作区内的能力、知识、洞察和内容原子发布版本。
- `Personal Overlay`：一线个人成长层版本。

不得用 Core 版本替代机构运行时版本，也不得因 Core 升级而重置后两者。

## 默认安装与更新

新用户安装公共 Core 后说“开始设置”，初始化采访将工作区建在用户选择的业务目录，而不是 Skill 安装目录。已有用户更新 Core 后先运行环境检查；工作区 Schema 兼容时直接继续，确需迁移时先预览再显式执行。

需要检查版本和隔离边界时运行：

```text
python3 scripts/doctor.py [工作区]
```

需要向一线设备离线分发已审核机构运行时时，才运行 `scripts/build_team_skill_package.py`。该导出包不得回传或提交到公共仓库。
