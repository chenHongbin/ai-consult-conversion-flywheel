# 咨询主管每日经营工作台（v2.0）

## 核心闭环

管理者的目标不是听完更多录音，而是每天完成一个可验证的管理动作：

```text
发现团队断点 → 找到正反样本 → 生成单动作训练 → 一线执行
→ 复查新样本 → 验证行为/结果 → 晋升团队能力
```

最小输入是一通录音、一段微信或一张截图。拿不到同一患者的完整历史时，仍然按独立沟通片段分析；只有存在可核验关联时才合并。

## 管理者自然语言入口

| 用户表达 | 默认动作 |
|---|---|
| 开始今天的工作 | 刷新工作台，输出昨日简报、今日断点、待办和训练主题 |
| 复核今日重点 | 按 P0/P1/P2 读取待办及对应证据 |
| 生成晨会训练 | 围绕当前唯一团队断点生成正反对照和单动作练习 |
| 辅导这个员工 | 读取员工当前唯一训练动作与最近复查样本 |
| 完成/复查这个管理任务 | 使用 `record_management_action.py` 追加任务事件 |
| 复盘今天 | 汇总管理动作、完成情况、待复查事项和次日优先级 |
| 刷新咨询管理工作台 | 使用 `generate_management_dashboard.py` 手动重建本地HTML |

## 单条样本三层输出

每次完成咨询分析后，同时生成：

1. **患者推进**：患者当前不确定什么、下一步服务动作、回复草稿、内容素材处方；
2. **员工辅导**：做对的一个动作、当前一个能力缺口、下次只改什么；
3. **团队学习**：是否重复出现、是否有优秀对照、是否进入女娲候选。

使用 `record_communication_sample.py` 将结构化结论写入追加式真源。原始录音、聊天和分析报告仍保留在原目录。

## 工作台生成

```bash
python3 scripts/generate_management_dashboard.py <工作区> --period today --date YYYY-MM-DD
```

页面输出：

`08_团队管理/04_团队报告/04_数据看板/咨询管理工作台.html`

页面只读、断网可用，不直接修改底层文件。主管点击“复制指令”后回到 Skill 执行；执行结果写入 JSONL，再刷新页面。

## 数据与判断规则

- 团队断点按“受影响员工数 → 独立样本数”排序；没有证据时显示证据不足。
- 每名员工每周期只保留一个主要训练动作。
- `unknown/missing` 不能转换为数字零。
- 没有预约、到院或成交数据时，只描述行为变化和节省时间，不宣称转化提升。
- 工作台不是员工排行榜，不自动产生绩效或人事结论。

## 女娲三链

能力候选除了销冠全链路，还要记录：

- 个性化服务链：患者信息 → 咨询师识别 → 针对性回答/素材 → 患者反应；
- 安心感形成链：患者不确定性 → 信息/选择/路径 → 自主感和继续交流；
- 团队复制链：销冠动作 → 训练 → 普通咨询师复查 → 行为/结果验证。

使用 `promote_team_capability.py` 执行五级晋升，不得手工跳级：

`候选经验 → 可训练动作 → 行为已验证 → 结果已验证 → 团队正式能力`。
