# 首次使用向导（v1.0）

## 目标

让没有软件使用经验的咨询主管在几分钟内完成三件事：创建工作区、接管已有资料、启动首次全量蒸馏。

## 前台交互

### 1. 先建立工作区

如果当前工作空间已有其他资料，自动做只读盘点，不移动、不改名、不上传原文件。当前选择的工作空间根目录就是首次全量扫描边界；Skill 在这里建立 `咨询转化工作区/` 和后台资料索引。

Skill 不默认写入桌面、文档、下载或其他未指定目录。

前台只说：

> 我先帮你建一个咨询转化工作区。以后机构资料、咨询录音、培训记录和分析结果都放在这里。

如果检测到当前空间已经有大量录音但没有机构资料，前台改为：

> 我发现你已经有一批咨询录音。我们可以先蒸馏咨询行为，生成临时能力包；机构价格、医生、地址和流程等事实，等你补充资料后再绑定。

### 2. 只问两个问题

1. 机构名称和当前负责的科室；
2. 资料主要放在哪里：电脑文件夹、IMA，还是两种都用。

其他信息在用户第一次分析、第一次生成话术或第一次陪练时按需补充。

### 3. 给用户八个能看懂的文件夹

```text
01_机构介绍
02_科室项目与服务
03_咨询流程与标准
04_优秀咨询案例
05_普通失败与未预约案例
06_团队培训与反馈
07_我的产出
08_团队管理
```

`08_团队管理` 第一版只建立一个主管团队，前台只显示“成员、团队会议、团队数据、团队报告”四个入口；日期、资料类型和后台归档由 Skill 自动完成。管理者每周可以说“生成本周团队报告”；默认每月进行一次员工一对一沟通，报告只提取与工作相关的事实。首次建立团队时询问主管姓名和成员名单，成员文件夹使用 `员工编号_姓名`。

用户不需要准确分类。放错位置时，Skill 自动识别并在后台建立正确索引；只有机构、科室、结果和是否允许团队学习这三个关键字段异常时才追问。

### 4. IMA 适配

- 在 WorkBuddy、Trae、Codex 或普通本地环境中：先检查是否已有 IMA 凭证；没有时不阻塞本地模式。
- 在 IMA 原生环境中：使用宿主提供的登录上下文，不重复索取 Client ID 和 API Key。
- 接入 IMA 后：先列出知识库名称和简介，让用户选择；不根据历史示例或默认名称猜测知识库。
- 读取知识库前：记录当前用户选择、用途、授权状态和科室范围。

### 5. 夜间自动化

WorkBuddy、Codex 或其他 Agent 可以在每天 22:00 调用 `scripts/run_nightly_cycle.py`，扫描成员待处理资料、成员日期目录和团队会议目录，生成去重任务队列；调用 `scripts/run_full_distillation.py` 时，按资料索引只处理新增或发生变化的咨询资料。电脑关机或 Agent 未运行时，下一次任务自动补跑。

### 6. 第一次价值交付

不要求用户先整理几十条资料。第一次说“蒸馏销冠”时，Skill 自动扫描当前工作空间并处理全部候选资料；如果用户明确说“分析这条”，才只生成单条“咨询复盘卡”。首次全量蒸馏完成后再提示：

> 如果你愿意，把更多优秀、普通或未预约案例放进对应文件夹，我可以继续帮你蒸馏成专属能力。

### 7. 没有机构知识库时

允许直接从录音开始，但必须走“临时咨询能力包”路径：先盘点、转写、标签、优秀与失败对照、候选行为卡、固定测试，再影子运行。没有机构资料时，不得生成真实价格、医生、地址、疗效、治疗周期或机构流程。完整的逐步提示词见 [initialization-and-distillation-prompts.md](initialization-and-distillation-prompts.md)。

## 后台状态

用户只看到“准备中、可以分析、正在学习、已更新”四种状态。技术处理记录放在 `_系统/`，包括转写、OCR、案例标准化、蒸馏候选、评估和版本记录。

## 失败处理

任何资料读取失败都不让用户理解 API、媒体 ID 或游标。只显示：

- 可以继续使用其他资料；
- 这份资料暂时无法读取；
- 你可以稍后重试或换一种方式提供。
