## 四层能力

1. **通用底座**：阶段判断、需求识别、沟通推进、预约、回访、团队教练和安全边界。
2. **机构事实**：科室、病种、项目、医生、价格、流程、服务和渠道事实。
3. **团队经验**：优秀行为、常见失败、异议处理、回访节奏和团队语言风格。
4. **持续记忆**：经审核的规则、标杆卡、训练题、反例和管理者反馈。

通用底座可以跨机构复用；机构事实和团队经验必须隔离；持续记忆必须有版本。

## 机构与科室隔离

使用一个 Skill，维护多个机构/科室档案：

```text
机构
└── 科室/病种/项目档案
    ├── 机构事实
    ├── 渠道上下文
    ├── 团队成员
    ├── 案例与结果
    └── 已审核能力包
```

每次分析绑定一个活动档案。多个渠道可以共用一个科室档案，但不能让不同科室的价格、医生、流程和案例混用。

## 案例卡

每个案例尽量记录：

- `case_id`：内部编号；
- `department`：科室/病种/项目；
- `channel`：获客渠道；
- `consultant`：咨询师，可脱敏；
- `medium`：微信、电话、录音或其他；
- `stage`：咨询阶段；
- `patient_intent`：患者目的；
- `concerns`：顾虑与异议；
- `actions`：咨询师关键动作；
- `outcome`：未留资、已留资、已预约、到院、爽约、未确认等；
- `evidence`：原文、消息位置或录音时间点；
- `authorization`：使用授权状态；
- `quality`：优秀、普通、失败、反例或待确认。

### 结果事件

不要用一个“转化成功/失败”字段概括全部结果。按时间记录事件：有效接待、有效沟通、同意留资、预约、到院、检查/面诊、治疗、爽约、拒绝、失联或停止联系。每个事件绑定时间、原因、渠道、科室、咨询师和结果来源；预约成功不自动等于咨询质量优秀。

### 咨询师成熟度

用能力层级服务不同人，而不是给所有人同样的报告：

| 层级 | 重点 | 训练证据 |
|---|---|---|
| 新人 | 听清主诉、相关回应、基本记录和边界 | 陪练与逐条反馈 |
| 合格 | 能独立完成阶段推进和下一步确认 | 连续可比案例 |
| 独立 | 能处理常见顾虑并完成透明回访 | 不同渠道案例 |
| 骨干 | 能稳定复制并解释行为条件 | 正反案例对照 |
| 主管教练 | 能辅导他人并沉淀规则 | 团队训练结果 |

等级只用于选择训练方式，不自动用于绩效或人事决定。

用于蒸馏和评估时，还必须记录：

- `source_nature`：真实对话、教学示例或方法模板；
- `source_hash`：原始证据指纹；
- `dedup_cluster_id`：去重内容簇；
- `outcome_provenance`：结果是否经机构确认；
- `outcome_window`：结果观察窗口；
- `label_confidence`：标签置信度；
- `review_status`：人工审核状态；
- `counterexample_ids`：对应边界或反例；
- `split`：开发、验证或测试；
- `safety_flags`：隐私、临床、虚构、强迫和外部动作风险；
- `clinical_boundary`：是否必须转执业人员；
- `consent_status`：是否允许团队学习；
- `transcript_quality`：录音、OCR 或文本质量。

预约成功不自动等于高质量案例；要同时观察事实准确、患者理解、下一步清晰、隐私边界和后续结果。

## 数据分层

| 层级 | 作用 | 运行时规则 |
|---|---|---|
| 原始证据 | 音频、原图、HTML、原始文档 | 不修改，不默认检索 |
| 标准化证据 | 转写、OCR、角色、时间点 | 受控引用 |
| 机构事实 | 服务、医生、项目、价格、流程 | 版本管理后使用 |
| 个案数据 | 某个患者的上下文 | 严格隔离，不进入公共知识 |
| 候选规则 | 从案例推断出的经验 | 必须人工审核 |
| 已发布能力包 | 当前可使用的规则与标杆 | 运行时优先读取 |
| 评估集 | 固定案例与红队反例 | 只用于验证 |
