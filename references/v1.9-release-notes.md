# v1.9 发布说明：基础咨询运行时 + 专项能力路由

## 这次解决什么问题

v1.8 的能力已经覆盖基础分析、蒸馏、团队发布和个人成长，但“安装后没有蒸馏能不能马上用”和“总入口到底调用哪个专项能力”仍主要依赖模型理解。

v1.9 把它落成三层机制：

```text
基础咨询运行时（始终可用）
    + 团队运行时（有已发布团队包才启用）
    + 个人成长层（有个人资料才启用）
```

## 基础运行时

`runtime/base-runtime.json` 是机器可读的基础能力契约。它明确声明：

- 不需要蒸馏即可工作；
- 默认使用咨询转化八步法、通用咨询底座、医疗安全、单动作陪练和视觉素材能力；
- 没有机构事实时，不能编造医生、价格、地址、项目、疗效、周期和活动；
- 完成机构初始化或团队发布后，只是在基础层上叠加事实和团队规则。

`scripts/load_active_capability.py` 在没有 active 能力包时返回 `base_only`，同时返回 `can_analyze: true` 和 `runtime_mode`，不再把用户挡在“必须先蒸馏”之前。

## 专项路由

`references/specialist-routing.json` 是唯一的专项能力注册表。当前包含：

- 患者沟通诊断；
- 费用异议；
- 效果担忧；
- 信任建立；
- 到院前推进；
- 爽约与分阶段回访；
- 新人单动作陪练；
- 咨询视觉与跟进素材；
- 销冠完整链路蒸馏；
- Skill 版本迭代；
- 团队管理与复盘。

用户可以自然语言使用总入口，也可以通过 `--route <route_id>` 直接调用专项能力。路由器只识别任务、声明输入输出和权限，不生成患者回复，不替代八步法或机构知识审核。

```bash
python3 scripts/route_consultation.py "患者说费用太贵，帮我判断真实顾虑"
python3 scripts/route_consultation.py --route practice_coach
python3 scripts/route_consultation.py --list
```

主管专用任务在一线角色下返回 `manager_confirmation_required`，不会执行团队蒸馏、能力发布、回滚或团队私密资料读取。

## 运行时输出

每次路由会记录或返回：

```text
route_id
runtime_mode
matched_terms
references
required_inputs
output_contract
permission
```

这样可以知道本次回答来自基础方法、团队正式规则，还是个人成长层，也能解释为什么需要补充某类资料。

## 验收标准

- 空工作区可以直接分析咨询，不要求先蒸馏；
- “费用异议”“效果担忧”“信任建立”“爽约回访”“新人陪练”能路由到不同专项；
- 没有机构知识时明确显示通用模式，不生成机构事实；
- 主管蒸馏、版本发布和团队管理在一线角色下被拦截；
- 团队运行时和个人成长层出现时，基础层仍保留，且不覆盖个人历史。
