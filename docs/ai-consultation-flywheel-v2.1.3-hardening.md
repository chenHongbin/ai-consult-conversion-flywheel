# AI 咨询转化飞轮 V2.1.3：可信运行与发布加固版

## 第一性原理

医疗咨询团队不是为了“使用 AI”而使用产品。他们需要在不泄露患者资料、不混用未审核知识、不丢任务的前提下，每天找到最需要人工处理的患者和员工行为断点。

> 单一产品目标：让主管敢把真实资料交给系统，敢按系统给出的优先级做管理，并且任何结论都能回到原始证据。

## 实现范围

| 问题 | V2.1.3 实现 |
|---|---|
| 公共包泄露原始资料 | 精确 allowlist，构建前扫描 |
| 工作区路径分裂 | 全局 `workspace_paths.py` |
| 候选自审 | 独立审核账本和哈希绑定回执 |
| 发布后篡改 | release、package、runtime 三层哈希验证 |
| 内容资产伪造 | 状态机、真实证据、冻结正文、可撤销投影 |
| 内容无法团队复用 | 第四发布组件 `content_runtime` |
| IMA/本地双链路 | `source-artifacts.jsonl` 统一内容哈希和跨源去重 |
| 长截图依赖缺失 | Pillow 优先，macOS `sips` 降级，Tesseract 预检和 E2E 测试 |
| 每日队列并发 | 租约 token、终态保护、日期索引、可重放 outbox |
| 入口误路由 | 任务动词优先和复合路由 |
| 今日重点无患者顺序 | 患者级优先队列 |
| 团队断点双口径 | 日报与工作台共用同一函数 |

## 正式团队版发布闸门

1. 全部回归和 V2.1.3 对抗测试通过。
2. 长截图 OCR 在目标安装机实际通过。
3. 三类知识/能力候选已使用独立回执审核。
4. 四组件 release 发布后通过运行时加载检查。
5. 公共包与团队包重新构建，确认无原始患者材料、无主管私有工作区、无主管发布脚本。
6. 首个真实团队先做受控试运行；本版不宣称已证明转化率提升。

执行命令、边界和故障恢复见 [V2.1.3 可信运行规范](../references/v2.1.3-trusted-runtime.md)。
