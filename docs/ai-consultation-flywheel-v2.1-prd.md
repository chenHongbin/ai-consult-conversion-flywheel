# AI 咨询转化飞轮 V2.1 产品设计方案

**产品代号**：每日全量咨询复盘与员工辅导闭环
**版本**：V2.1
**日期**：2026-08-19
**需求完整度**：95/100
**状态**：可进入开发设计与试点

---

## 一、执行摘要

V2.1 不再把自己定义成“单通录音分析工具”，而是定义成咨询团队的**每日全量复盘系统**：一线咨询师或主管把微信长截图、电话录音和文本材料放进系统，系统按员工、对话、患者案例和日期组织材料，为每个有效案例生成标准分析；再从全部案例中筛出值得主管重点查看的风险案例、丢失案例、典型案例和新问题，最终形成员工日报、团队日报和训练卡。

V2.1 的核心价值是两件事：

1. 让主管从“抽查少数录音、凭印象带人”变为“全量覆盖、按证据辅导”。
2. 让员工从“听完点评但不知道怎么改”变为“每次只练一个动作，并在后续真实案例中复查”。

V2.1 暂不接入预约、到院、付款等业务结果，因此本版本承诺的是**管理提效、复盘覆盖和咨询行为改善**，不直接宣称已验证提升转化率。业务结果闭环留给 V2.2。

## 二、第一性原理

### 2.1 转化率真正由什么决定

转化率不会因为多了一份报告自动提高。它来自咨询师在关键时刻做出更好的判断和动作，例如：

- 更早识别患者真正的顾虑；
- 先建立信任，再解释方案；
- 不越过医疗安全边界；
- 在合适的时点推进下一步；
- 对同类问题能稳定重复正确动作。

因此系统最小闭环不是“材料 → 报告”，而是：

> 原始证据 → 识别断点 → 给出动作 → 针对训练 → 新案例复查 → 行为是否稳定

### 2.2 主管最稀缺的不是数据，而是注意力

假设一名主管管理 50 人，每人每天接待 10 个患者，就是 500 个患者案例。主管不可能认真阅读 500 份长报告。

所以产品原则必须是：

> **全量分析，重点呈现。**

系统应分析每个有效案例，但主管首页只呈现：

- 必须立即处理的安全和合规风险；
- 每名员工今天最主要的一个问题；
- 团队今天最共性的一个断点；
- 最值得学习和复盘的正反案例；
- 每名员工当前唯一的训练重点。

### 2.3 原始材料天然不完整

微信长截图可能缺页、顺序错误、角色不清；录音可能只有单声道、噪声大、缺少上下文；多个文件未必属于同一患者。

因此 V2.1 必须：

- 明确区分“事实、推断、未知”；
- 所有关键判断都能回到截图位置或录音时间点；
- 患者归并只做建议，未经人工确认不得自动合并；
- 材料质量不足时降低置信度或进入待确认区，不得编造完整故事。

### 2.4 低学习成本是产品能力，不是帮助文档

目标用户不应学习任务队列、对象 ID、提示词或模型参数。默认体验只保留四个动作：

1. 建立机构；
2. 分析这一条；
3. 分析今天全部咨询；
4. 查看今天重点。

技术配置、文件命名、任务重试和报告归档由系统承担。

## 三、目标用户与价值

### 3.1 一线咨询师

**现状问题**：不知道自己的对话哪里有问题；收到的点评抽象、滞后，无法马上练习。
**V2.1 价值**：上传自己的微信截图或录音，即刻得到基于证据的单案复盘和一个可执行训练动作。
**权限**：只能查看自己的材料、报告和训练，不得查看其他员工或团队管理数据。

### 3.2 咨询主管

**现状问题**：管理 10—50 人时无法逐人逐案复盘，只能抽查，辅导容易依赖印象。
**V2.1 价值**：系统每天完成全量基础复盘，主管把时间集中在异常、风险、重复短板和关键训练上。
**权限**：查看所辖员工、团队汇总，确认患者归并，调整重点案例，发布训练任务。

### 3.3 咨询总监/机构负责人

**现状问题**：知道结果好坏，但不知道团队具体卡在哪个行为环节，也不知道优秀做法能否复制。
**V2.1 价值**：看到团队共同断点、管理覆盖情况、优秀动作和训练进展，为流程、培训和资源配置提供依据。
**权限**：查看机构级汇总和已发布的团队能力，不默认接触不必要的患者原始隐私。

## 四、每日、每周、每月使用场景

### 4.1 每日

**一线咨询师**

- 把一通录音或一组微信长截图直接发给 Skill；
- 获得单案报告、可直接参考的下一步表达和当天唯一训练动作；
- 在下一次相似患者对话后再次提交，检查训练动作是否出现。

**咨询主管**

- 员工材料进入各自的“今天放这里”文件夹，或由主管直接上传；
- 夜间自动分析，也可手动点击“分析今天全部咨询”；
- 第二天只查看团队重点页；
- 对患者归并建议、重点案例和训练卡做必要确认；
- 需要时打开任一患者或任一员工的完整证据报告。

### 4.2 每周

- 查看每名员工反复出现的长板和短板；
- 复查上周训练动作是“出现一次”还是已经“稳定”；
- 选择团队正反案例做周会复盘；
- 只保留每名员工一个当前训练重点，避免同时训练过多动作；
- 把跨员工、跨案例重复验证的优秀动作提名为团队候选最佳实践。

### 4.3 每月

- 查看团队各咨询阶段的能力分布和反复断点；
- 检查主管是否完成了重点案例辅导和训练复查；
- 审核哪些优秀动作可以晋升为机构能力包；
- 清理过期规则、冲突规则和缺少证据的历史结论；
- 为 V2.2 的业务结果接入保留同一批案例 ID 和员工 ID。

## 五、V2.1 产品边界

### 5.1 本版本必须实现

- 微信长截图、电话录音、纯文本的单案分析；
- 以员工为入口的每日批量处理；
- 全量标准分析和重点案例深度分析；
- 患者跨材料归并建议与人工确认；
- 患者/案例报告、员工日报、团队日报、训练卡四层输出；
- 训练动作在后续真实案例中的行为复查；
- 夜间自动运行和手动补跑；
- 失败可见、可重试、不中断其他任务；
- 管理者与一线员工的权限隔离；
- 所有关键结论的证据定位和版本记录。

### 5.2 本版本明确不做

- 不自动读取个人微信数据库；
- 不根据相似姓名、病种或表述自动认定同一患者；
- 不接入预约、到院、付款和退款结果；
- 不计算或宣称真实转化率提升；
- 不把患者原始材料写入团队通用 Skill；
- 不做无人工授权的自动对外发送；
- 不允许模型替代医生作诊断、疗效承诺或个体化医疗结论。

## 六、核心用户流程

### 6.1 单条即时分析

1. 用户上传微信截图、录音或文本。
2. 系统识别员工、渠道、材料类型和质量。
3. 系统完成 OCR/转写、角色识别、时间顺序恢复和隐私处理。
4. 系统生成一份“赖老师框架升级版”标准报告。
5. 若命中风险、流失、关键阶段或新问题，自动补充深度分析。
6. 一线用户获得自己的报告；主管还可把该案例加入员工训练或团队复盘。

### 6.2 团队每日批量分析

1. 材料进入 `08_团队管理/01_成员/<员工>/01_今天放这里`，直接上传材料也进入同一任务队列。
2. 夜间任务扫描、去重、预处理并创建分析任务。
3. 系统为每个有效对话生成标准报告。
4. 系统自动筛选深度分析案例，主管可增删。
5. 系统汇总员工日报、团队日报和训练卡。
6. 未完成、失败和待人工确认的任务独立列出，不影响已完成报告交付。

### 6.3 患者维度分析

1. 系统先把每个文件登记为原始材料，把连续的一次沟通登记为对话。
2. 根据同一上传包、用户提供的内部患者编号、文件夹结构或明确上下文，提出患者归并建议。
3. 主管确认、拒绝或暂不处理。
4. 只有确认后，多个微信对话和电话录音才能合并为一个患者案例报告。
5. 未确认材料继续按独立对话分析，不因等待归并而阻塞。

## 七、四层交付物

### 7.1 患者/案例报告：赖老师框架升级版

每个有效案例都必须包含：

1. **三行结论**：患者当前状态、主要顾虑、最关键下一步；
2. **材料完整度**：渠道、时间范围、缺失部分、识别质量；
3. **患者决策过程**：需求、信任、顾虑、意向和停滞点；
4. **八步阶段分析**：当前处于哪一步、已完成什么、缺了什么；
5. **咨询师做得好的地方**：动作、患者反馈、适用条件；
6. **错失机会与风险**：具体动作、造成的影响、证据位置；
7. **销冠/最佳实践对照**：同场景下应如何判断和推进；
8. **下一步动作**：最多三个，按优先级排序；
9. **安全表达草稿**：可以直接参考，但不能越过医疗边界；
10. **唯一训练动作**：该员工当前最值得练的一件事；
11. **证据定位**：截图页码/区域、原句或录音时间点；
12. **置信度与未知项**：不得把推断写成事实。

### 7.2 员工日报

员工日报从当天全部有效案例中生成，包含：

- 收到、完成、失败、待确认的案例数量；
- 当天已验证长板及出现案例数；
- 当天最主要短板及出现案例数；
- 咨询阶段和患者顾虑分布；
- 高风险、流失、典型正反案例入口；
- 与销冠/团队最佳实践的主要差距；
- 当前唯一训练卡和复查日期；
- 过去训练动作在新案例中的“未观察/已出现/已稳定”状态。

**判断阈值**：同一行为至少在 3 个独立患者案例中出现，且覆盖相关案例的 50% 以上，才能标记为“稳定长板”或“重复短板”；否则只标记为“当日观察”。

### 7.3 团队日报

主管首页只展示一屏重点：

- 团队材料总数、有效案例数、完成率和失败数；
- P0 医疗安全、隐私或合规风险清单；
- 每名员工今天最主要的一个问题；
- 团队今天最共性的一个断点；
- 最值得学习的正案例和最值得复盘的负案例；
- 当天新增问题、冲突规则和知识缺口；
- 完整员工日报和案例报告的下钻入口。

**团队断点阈值**：普通问题至少跨 2 名员工、出现在 3 个独立患者案例中，才能标记为团队断点；P0 风险不受该阈值限制。

### 7.4 训练卡

每张训练卡只训练一个动作，包含：

- 触发场景；
- 当前常见错误；
- 销冠/最佳实践的判断逻辑；
- 推荐动作和安全表达；
- 一次模拟练习；
- 明确通过标准；
- 下一次真实案例的抽检条件；
- 复查日期和状态。

每名员工默认只允许一个“进行中”训练动作。新问题先进入候选区，除非主管手动替换当前训练。

## 八、全量标准分析与重点深度分析

### 8.1 标准分析覆盖全部有效案例

标准分析负责回答：发生了什么、患者卡在哪里、咨询师做对/做错什么、下一步怎么做、证据在哪里。

“有效案例”是指材料可读取、能识别基本对话角色、包含足够咨询内容。低质量或损坏材料进入待处理区，不得静默丢弃。

### 8.2 深度分析的自动筛选规则

以下情况默认进入深析：

- 医疗安全、隐私、承诺或合规风险；
- 患者明确拒绝、失联、投诉或高意向后停滞；
- 处于关键推进阶段但没有下一步；
- 出现团队未见过的新问题或新异议；
- 代表性强的优秀或失败案例；
- 主管手动指定。

主管可以增删深析对象，但不能取消 P0 风险标记和证据保留。

## 九、底层对象与数据合同

### 9.1 六层对象

| 层级 | 对象 | 含义 |
|---|---|---|
| 1 | `artifact` | 一张截图、一段录音或一个文本文件 |
| 2 | `conversation` | 一次连续微信沟通或一通电话 |
| 3 | `patient_case` | 经确认属于同一患者的一个或多个对话 |
| 4 | `consultant_day` | 某员工某天的全部案例集合 |
| 5 | `team_day` | 某团队某天的全部员工集合 |
| 6 | `learning_chain` | 断点、训练动作和后续复查记录 |

### 9.2 稳定 ID

V2.1 新增并贯通以下 ID：

- `artifact_id`
- `conversation_id`
- `patient_case_id`
- `consultant_day_id`
- `team_day_id`
- `analysis_task_id`
- `training_action_id`
- `learning_chain_id`

所有报告、任务、证据和训练记录都必须携带对应 ID，避免几份台账无法互相追溯。

### 9.3 患者归并状态

`ungrouped → suggested → confirmed/rejected`

归并建议必须记录理由和使用的信号。相似姓名、病种、城市、说话方式等弱信号不得单独触发自动合并。患者标识只在机构工作区内使用匿名 ID。

### 9.4 任务状态

`discovered → prepared → claimed → processing → completed/partial/failed/quarantined`

- 同一源文件哈希、分析合同版本和作用域不得重复生成报告；
- 任务领取采用 30 分钟租约，超时后可被重新领取；
- 自动重试最多 2 次，第三次进入失败区并提示人工处理；
- 失败任务不得阻塞其他任务；
- 原始材料永不被自动删除或覆盖。

### 9.5 结果预留字段

V2.1 保留 `appointment_status`、`arrival_status`、`payment_status`、`refund_status` 等字段，但统一为 `unknown`，不得用于计算转化或晋升最佳实践。V2.2 接入结果后复用同一案例链路。

## 十、知识、证据和版本设计

V2.1 借鉴 GBrain 的思想，但只采用与当前场景直接相关的部分：

### 10.1 不可变事件层

原始材料登记、OCR/转写、分析、主管确认、训练发布、复查和规则晋升都以追加事件保存。历史不覆盖，便于追责和重建。

### 10.2 可重建当前结论层

员工长短板、团队断点、当前训练和机构最佳实践是事件的当前投影，可随新证据更新。若投影损坏，可从事件重建。

### 10.3 单一生效版本

基础八步法、机构事实、销冠流程和团队能力包必须有明确的生效版本。分析优先级固定为：

> 医疗/安全硬规则 > 已确认机构事实 > 当前生效机构能力包 > 基础八步法

### 10.4 最小上下文包

单案分析只加载该案例、该员工当前训练、相关机构事实和当前最佳实践，不把整个团队历史全部塞入模型，降低混淆、泄露和成本。

### 10.5 能力晋升门槛

单个优秀案例不能直接成为团队规则。候选动作必须经过多案例证据、主管审核、无安全冲突和版本发布，才能进入机构能力包。

## 十一、自动化与运行架构

### 11.1 双入口、同一流水线

- **文件夹入口**：适合主管批量放入各员工当天材料；
- **直接上传入口**：适合一线或主管即时分析一条材料。

两种入口最终都创建同一种任务和报告，避免两套逻辑产生不同结论。

### 11.2 平台中立核心 + 主机适配器

- 核心 Python 层负责扫描、哈希去重、任务状态、对象关联、聚合和报告落盘；
- Agent 主机负责 OCR/转写后的语义分析和报告生成；
- 优先提供 WorkBuddy/Codex 的夜间调度适配器；
- Claude/Trae 先支持手动运行，后续补调度适配器。

### 11.3 默认运行参数

- 首次建立机构时一次性请求夜间调度授权；
- 默认每天 22:30 开始，用户可用自然语言修改；
- 每批领取 20 个分析任务；
- 主机支持时并发 4 个，否则顺序执行；
- 单次夜间窗口默认 4 小时，可续跑未完成队列；
- 主管可随时执行“分析今天全部咨询”或补跑失败项；
- 次日首页必须同时显示已完成、处理中、失败和待确认数量。

### 11.4 面向用户的目录

- 员工上传：`08_团队管理/01_成员/<员工>/01_今天放这里`
- 员工报告：员工目录下 `03_个人报告`

## 十二、权限、隐私与医疗安全

- 原始患者材料默认保存在本地工作区；
- 团队通用 Skill 只允许写入经审核的通用规则，不包含患者原文和员工个人报告；
- 一线员工只能访问本人材料、报告和训练；
- 主管只能访问所辖团队；
- 总监默认查看聚合信息，下钻原始材料需具备相应权限；
- 输出中的手机号、身份证号、地址等敏感信息默认脱敏；
- 医疗诊断、疗效保证、替代医生决策和不当承诺统一触发安全边界；
- P0 风险必须优先展示，不参与普通能力晋升；
- 未确认患者归并不得造成跨患者材料泄露。

## 十四、验收标准与 ConsultBench

### 14.1 功能验收

- 同一材料重复提交不会产生重复报告；
- 微信长截图能够分段、保序、去重并保留重叠区域；
- 录音报告能定位到时间点并区分角色；
- 每个有效案例都有标准报告；
- 自动深析命中规则正确，主管可调整；
- 患者归并建议可以确认、拒绝和暂缓；
- 只要员工当天有一个成功案例，就能生成员工日报；
- 只要团队当天有一个成功员工日报，就能生成团队日报；
- 失败任务可重试，已成功结果不被覆盖；
- 一线、主管和总监权限隔离生效。

### 14.2 输出质量基准集

建立至少 60 个经人工标注的真实脱敏或高仿真测试案例，覆盖：

- 微信长截图、电话录音、文本和跨渠道患者包；
- 高意向、低意向、拒绝、失联、投诉和正常推进；
- 医疗风险、隐私风险、承诺风险和未知信息；
- 同一员工 10 个患者的日聚合；
- 多员工团队聚合；
- 销冠流程存在、缺失和冲突；
- 材料缺页、乱序、噪声、角色不清和重复上传。

硬性通过线：

- P0 安全案例正确升级率 100%；
- 关键结论证据可追溯率 100%；
- 跨员工或跨患者泄露 0；
- 未确认归并自动生效 0；
- 队列重复、丢失 0；
- 不知道的信息明确标记为未知，不得臆造；
- 无业务结果时不得输出转化提升结论。

### 14.3 规模验收

使用“50 名员工 × 每人 10 个患者 = 500 个案例/天”的合成任务进行压力测试：

- 分批处理可暂停、续跑和重试；
- 无重复、无静默丢失；
- 部分失败不影响其余报告；
- 团队重点页仍保持一屏核心信息；
- 主管可从团队 → 员工 → 患者 → 原始证据逐层下钻。

## 十七、最终产品判断

V2.1 的完成标准不是“又多了几个分析脚本”，而是以下一句话能够真实成立：

> 主管把团队当天的微信截图和录音放进去，第二天只需看一页重点，就知道哪些患者要马上处理、每名咨询师最该改什么、今天团队共同卡在哪里；每个判断都能回到原始证据，每个短板都能变成训练，并能在后续真实咨询中复查。

若只完成单通分析，没有真正执行批量队列、员工日聚合、团队重点和训练复查，就仍属于 V2.0 增强版，不能称为 V2.1。
