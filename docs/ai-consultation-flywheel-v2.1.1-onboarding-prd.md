# AI 咨询转化飞轮 V2.1.1 首次设置向导产品设计

**产品代号**：第一次就跑起来
**版本**：V2.1.1
**日期**：2026-08-20
**需求质量评分**：94/100
**状态**：可进入交互设计与开发

---

## 一、执行摘要

V2.1 已经具备逐案分析、员工和团队聚合、患者跨渠道归并、单动作训练和后续复查等后台能力，但第一次使用仍然需要用户理解工作区、成员目录、调度授权和不同配置文件。对于没有软件使用经验的咨询主管，这会直接阻断产品价值。

现有 `ai-consult-onboarding` Skill 提供了一个很好的起点：它通过角色、机构、渠道、场景、顾虑、输出偏好和合规红线，让 WorkBuddy 更理解用户，并用一条真实失败对话展示价值。但它目前只解决“懂人”，没有完成飞轮真正需要的“建工作区、建团队、验证第一条材料、安装自动运行”。如果把八题采访原样接到飞轮前面，用户虽然完成了画像，产品仍然没有开始每日复盘。

V2.1.1 应把初始化采访能力内嵌为飞轮的首次设置编排器。首次设置不追求一次问全，而追求最短时间完成一条可信价值链：

> 识别角色 → 确认机构作用域 → 建立本人或团队 → 创建工作区 → 分析第一条真实材料 → 展示价值 → 授权自动运行 → 进入每日使用

用户只安装一个 Skill。独立的初始化采访 Skill 保留为研发和兼容入口，正式用户不需要理解两个 Skill 的关系。

## 二、第一性原理

### 2.1 首次设置的目标不是收集更多信息

首次设置的唯一目标是让用户尽快获得一次可信结果，并让系统具备下一次自动工作的条件。

一条信息只有在能够改变以下至少一项时，才值得在首次设置中询问：

1. 分析范围；
2. 权限边界；
3. 报告归属；
4. 自动运行方式；
5. 安全和合规边界；
6. 首次结果是否可信。

不能改变系统行为的信息，不在首次设置中阻塞用户。

### 2.2 用户不是来接受采访的

用户的任务是管理咨询团队或改进自己的咨询，不是帮助系统完善画像。因此产品前台不用“接受采访”“建立画像”等抽象表达，统一使用：

> 我先帮你把机构和团队设置好，再用一条真实咨询验证。大约 5 分钟。

### 2.3 信任必须先于自动化授权

用户在尚未看到结果时，很难理解为什么要授权夜间自动运行。正确顺序是：

> 先分析一条真实材料 → 用户确认有价值 → 再请求一次自动运行授权

### 2.4 配置必须有唯一真源

机构、角色、成员、调度和合规信息不能同时散落在画像 Markdown、`USER.md`、`MEMORY.md`、来源配置和工作区状态中并各自演化。

飞轮工作区中的结构化配置是唯一真源；WorkBuddy 的 `USER.md` 和 `MEMORY.md` 只接收经过确认的投影内容。投影失败不能影响飞轮本地运行。

### 2.5 画像应该在使用中成长

渠道、常见顾虑、高频场景和个人表达偏好可以从后续真实材料与用户纠正中持续学习。首次设置只采集最少必要信息，不要求用户一次回忆完整。

## 三、现有初始化采访能力的取舍

| 现有问题或能力 | V2.1.1 处理方式 | 原因 |
|---|---|---|
| 机构、科室、主推项目 | 保留为必填，但允许项目稍后补充 | 决定知识和分析作用域 |
| 获客渠道 | 可选；能从首条材料确认时不再问 | 有助于节奏判断，但不应阻塞运行 |
| 一线/主管角色 | 提升为第一题 | 决定权限、后续问题和首页入口 |
| 每天最常做的三件事 | 移出必填，后续从使用行为学习 | 不影响首次分析能否运行 |
| 失败对话钩子题 | 升级为“第一条真实材料验证” | 是首次价值交付，不只是演示 |
| 三句常见顾虑 | 改为可选补档或从真实案例聚合 | 用户回忆容易产生偏差，真实证据更可靠 |
| 输出偏好 | 使用默认值，用户纠正后再记忆 | 不值得在首次设置中增加一轮确认 |
| 机构禁用表达 | 保留可选补充；通用医疗红线自动生效 | 安全规则必须存在，但用户不一定能完整回答 |
| 完整模式四题 | 移至后续“完善我的设置” | 团队结构中的成员名单除外 |
| 每题都问是否允许写入 | 改为草稿自动保存、最终一次确认 | 八次确认增加认知负担；敏感资料仍独立确认 |
| 写入画像 Markdown | 保留为可读报告，不作为唯一真源 | 便于用户查看，但程序应读取结构化配置 |
| 修改 USER.md/MEMORY.md | 改为带管理标记的局部投影 | 防止覆盖用户已有配置和形成双重真源 |

### 3.1 关于客单价

客单价不是首次设置必填项。一线咨询师不询问。主管在后续配置机构知识或业务结果口径时可以确认价格档位，但不能把个人估计直接当成机构事实。

### 3.2 关于“同一患者”

首次设置不要求用户理解患者 ID。首条材料如果同时包含微信和录音，只提示：

> 这两份材料看起来可能属于同一位患者，要合在一起分析吗？

只有用户确认后才创建患者组合报告。

## 四、产品定位与角色

### 4.1 一句话定位

让医疗咨询主管或咨询师安装后 5 分钟完成设置，并用第一条真实咨询确认 AI 已经能够按其机构、角色和团队范围工作。

### 4.2 主管用户

主管首次设置需要完成：

- 确认机构和部门；
- 确认自己是主管；
- 导入咨询师名单；
- 创建每名成员的投放入口；
- 验证一条真实材料；
- 选择自动分析时间并授权一次；
- 获得“今日重点”入口。

### 4.3 一线咨询师

一线首次设置只需要：

- 确认机构和部门；
- 确认本人身份；
- 上传第一条自己的咨询；
- 获得单案复盘和一个训练动作。

一线不创建团队、不安装全团队夜间任务，也不能查看他人材料。

## 五、统一入口

首次安装后只显示：

> 开始设置

也支持自然语言触发：

- 建立我的机构；
- 第一次设置；
- 初始化我的咨询助手；
- 让 AI 更懂我；
- 建立我的团队。

系统检测到设置未完成时，用户直接说“分析今天全部咨询”也会自动进入未完成步骤，不要求先学习正确口令。

设置完成后，主管首页固定为：

1. 分析这一条；
2. 分析今天全部咨询；
3. 查看今天重点；
4. 查看某个咨询师。

一线首页固定为：

1. 分析这一条；
2. 帮我回复；
3. 安排回访；
4. 陪我练一遍。

## 六、自适应首次设置流程

### 阶段 0：自动盘点，不向用户提问

系统只读检查：

- 当前宿主是否为 WorkBuddy、Codex、Claude、Trae 或普通本地环境；
- 飞轮工作区是否已存在；
- 机构、部门、角色、成员和调度是否已有确认值；
- `USER.md`、`MEMORY.md` 和已有画像中是否有可复用内容；
- OCR、YouNavi 和本地文件访问是否可用；
- 是否已经有一条可以试跑的材料。

已有信息只向用户做一次汇总确认，不重复采访。

### 阶段 1：先确认角色

问题：

> 你主要是自己做咨询，还是管理一个咨询团队？

选项：

- 我是一线咨询师；
- 我是咨询主管/总监。

作用：决定权限、工作区类型、成员导入和首页入口。

### 阶段 2：确认机构作用域

问题：

> 你负责哪家机构、哪个科室或部门？如果有主推项目，也可以一起告诉我。

系统生成草稿：机构、部门、项目。用户只确认异常项。

禁止把用户口述的医生、价格、疗效和资质自动写成已确认机构事实。

### 阶段 3A：主管导入成员

问题：

> 把咨询师名单发给我就行。可以粘贴姓名、上传 Excel，或者发一张名单截图。

系统自动完成：

- 识别姓名和已有员工编号；
- 缺少编号时生成内部编号；
- 展示识别结果；
- 只让主管处理重名、缺失和识别不清项；
- 创建每名咨询师的“今天放这里”和个人报告目录。

允许选择“先添加 1 个人试用”，不因为完整名单缺失而阻塞第一条分析。

### 阶段 3B：一线确认本人

问题：

> 报告里怎么称呼你？如果机构有员工编号，也可以一起告诉我。

只创建本人的个人作用域。

### 阶段 4：建立并校验工作区

后台严格调用标准初始化和校验流程。前台只显示：

> 已经准备好。以后把截图和录音放进“今天放这里”，不用改文件名。

内部必须完成：

- 创建标准工作区；
- 写入角色、机构、部门和成员结构化配置；
- 校验为 `canonical`；
- 检测 OCR 和录音转写能力；
- 生成设置草稿和可恢复状态。

### 阶段 5：用第一条真实材料交付价值

问题：

> 现在发一张微信长截图、一通电话录音或一段文字。我先帮你分析一条，确认设置是对的。

系统自动：

1. 检查并脱敏直接标识；
2. 切片/OCR或转写；
3. 使用V2.1统一逐案合同分析；
4. 输出一屏结果：患者卡点、咨询师一个关键动作、下一步和证据；
5. 主管额外看到员工归属是否正确；
6. 询问“这份判断是否基本符合你的实际情况”。

如果用户暂时没有材料，允许跳过；状态显示“设置完成，首条验证待完成”，不能假装已经可稳定分析。

### 阶段 6：看到价值后授权自动运行

仅主管触发：

> 要不要每天自动处理新增材料？默认晚上 22:30，你也可以换一个时间。只需要授权这一次。

用户确认后，宿主适配器必须真实创建调度任务并回读验证。只有回读成功才显示：

> 每日自动复盘已开启。

如果当前宿主没有调度能力，显示：

> 当前环境暂时不能自动运行。我已经保留“分析今天全部咨询”手动入口，数据和报告完全相同。

不得只写入 `自动化配置.json` 就宣称已完成授权。

### 阶段 7：完成页

主管只看到：

```text
设置完成

机构：XX机构 · XX科室
团队：10名咨询师
第一条分析：已通过 / 待验证
每天自动分析：22:30 已开启 / 未开启

你以后只需要：
1. 把资料放进对应咨询师的“今天放这里”；
2. 第二天打开“查看今天重点”。
```

页面不显示队列、患者 ID、任务 ID、哈希、配置文件路径和模型名称。

## 七、渐进补档

以下内容不阻塞首次设置：

- 获客渠道；
- 决策周期；
- 高频工作场景；
- 三句常见到院阻力；
- 输出风格；
- 机构额外禁用表达；
- 团队考核口径；
- 三个月学习目标。

补档来源按优先级为：

1. 用户明确确认；
2. 真实材料中的可核验事实；
3. 多案例聚合形成的候选；
4. AI 推断，仅作为待确认，不能转正。

触发方式：

- 更新我的设置；
- 记住这个偏好；
- 我们换科室了；
- 新增一个咨询师；
- 修改自动分析时间。

系统不得每周主动弹出完整采访。只有某个缺失字段真正影响当前任务时，才追问一个问题。

## 八、数据与文件设计

### 8.1 唯一真源

建议新增：

```text
_系统/首次设置/
├── onboarding-state.json
├── onboarding-events.jsonl
├── confirmed-profile.json
└── projections.json
```

`confirmed-profile.json` 保存经过用户确认的结构化配置：

```json
{
  "schema_version": "2.1.1-onboarding-profile",
  "role": "manager",
  "institution": "XX机构",
  "department": "口腔",
  "projects": ["种植", "正畸"],
  "employee_scope": ["A001", "A002"],
  "channels": [],
  "output_preferences": {},
  "institution_prohibitions": [],
  "first_case_status": "completed",
  "automation_status": "verified",
  "schedule": "22:30",
  "confirmed_at": "2026-08-20T12:00:00+08:00"
}
```

### 8.2 投影关系

| 信息 | 结构化真源 | 兼容投影 |
|---|---|---|
| 机构、部门、项目 | `confirmed-profile.json` | `_系统/状态.json`、`_系统/来源配置.json` |
| 角色和权限 | `confirmed-profile.json` | `_系统/运行时角色.json` |
| 成员名单 | `confirmed-profile.json` | 成员目录、来源配置中的团队字段 |
| 自动运行时间 | `confirmed-profile.json` | `_系统/自动化配置.json`、宿主调度器 |
| 输出偏好 | `confirmed-profile.json` | WorkBuddy `USER.md` 管理区块 |
| 机构额外红线 | `confirmed-profile.json` | 机构安全配置、WorkBuddy `MEMORY.md` 管理区块 |
| 可读画像 | `confirmed-profile.json` | `咨询师画像-当前.md` |

### 8.3 USER.md 与 MEMORY.md 安全写入

只允许更新带边界标记的区块：

```text
<!-- AI_CONSULT_ONBOARDING_START -->
...
<!-- AI_CONSULT_ONBOARDING_END -->
```

写前备份、显示变更摘要、写后校验。不得覆盖文件其他内容，不修改 `SOUL.md`。

### 8.4 可恢复状态机

内部状态：

```text
not_started
→ role_confirmed
→ organization_confirmed
→ team_or_identity_confirmed
→ workspace_verified
→ first_case_completed / first_case_deferred
→ automation_verified / manual_mode
→ ready
```

用户中途退出时从最近一个已确认状态继续，不重复创建工作区或成员。

## 九、宿主适配架构

### 9.1 编排层

飞轮主 Skill 负责：

- 识别首次设置意图；
- 按状态机只问当前一个问题；
- 调用工作区初始化；
- 调用第一条分析；
- 调用宿主调度适配器；
- 输出完成页和四个日常入口。

### 9.2 WorkBuddy 适配层

WorkBuddy 适配器负责：

- 检测和更新受控的 `USER.md`、`MEMORY.md` 区块；
- 创建、读取和验证定时任务；
- 保存最近一次调度结果；
- 在调度失败时通知用户并保留手动入口。

### 9.3 飞轮运行层

复用现有能力，不创建第二套分析逻辑：

- `init_consult_workspace.py`；
- `verify_consult_workspace.py`；
- `daily_review.py register/claim/complete/aggregate`；
- `run_nightly_cycle.py`；
- V2.1逐案报告合同；
- 患者归并、员工/团队聚合和训练复查。

### 9.4 独立初始化 Skill 的去留

正式产品中不再要求单独安装 `ai-consult-onboarding`。其采访问题、角色模板、画像字段和降级诊断作为飞轮内部 `onboarding` 子工作流保留。

独立 ZIP 可保留三种用途：

- WorkBuddy旧用户兼容；
- 培训课程单独演示；
- V2.1.1子流程的回归测试夹具。

## 十、功能需求与验收标准

### FR-1 自适应盘点

- 已有信息不重复询问；
- 飞轮旧工作区可以增量迁移；
- 不移动、不删除用户原有资料；
- 盘点失败不阻塞本地手动模式。

### FR-2 角色分流

- 主管和一线使用不同问题、权限和首页；
- 一线不能创建全团队分析任务；
- 主管仍可临时使用一线动作。

### FR-3 成员导入

- 支持粘贴、Excel和名单截图；
- 只要求处理重名和识别失败项；
- 重复导入不重复创建成员；
- 可以先用一名成员完成试跑。

### FR-4 第一条真实材料

- 微信长截图、录音和文本使用同一V2.1报告合同；
- 能回到原始证据位置；
- 无法识别时明确失败，不输出空报告；
- 未脱敏材料不写入学习区；
- 用户确认归属错误时可以更正员工和科室作用域。

### FR-5 自动运行授权

- 用户明确授权前不得创建系统定时任务；
- 授权后必须回读验证；
- 修改时间必须同步更新配置和宿主任务；
- 宿主不支持时明确进入手动模式；
- 电脑关机或任务失败后可以补跑。

### FR-6 首次设置完成定义

只有同时满足以下条件才显示“设置完成”：

- 角色已确认；
- 机构和部门已确认；
- 本人或至少一名团队成员已建立；
- 工作区校验为 `canonical`；
- 第一条分析已完成，或明确标记用户主动稍后验证；
- 自动运行已验证，或明确选择手动模式；
- 权限和隐私边界已生效。

## 十一、体验约束

- 一次只问一个问题；
- 默认必答交互不超过 5 轮；
- 不要求用户输入员工编号；
- 不要求用户整理或改名文件；
- 不展示技术状态名；
- 每一步都说明完成了什么和还差什么；
- 用户可以随时退出并继续；
- 默认值可以直接接受，不强迫逐字段确认；
- 第一条报告默认一屏，用户要求详细时再展开。

## 十二、成功指标

### 首次价值

- 安装到工作区可用：目标不超过 3 分钟；
- 安装到首条报告：目标不超过 5 分钟，不含长录音实际转写时间；
- 首次设置完成率：目标不低于 80%；
- 首条报告成功或明确失败率：100%，不得静默卡住。

### 零门槛

- 需要用户理解的技术概念数：0；
- 首次设置必答轮数：不超过 5；
- 重复询问已有字段数：0；
- 工作区重复创建数：0。

### 自动化

- 调度显示已开启但宿主实际不存在的情况：0；
- 自动运行失败可见率：100%；
- 手动与自动入口使用同一报告合同：100%。

### 可信度

- 关键判断证据可追溯率：100%；
- 未确认机构事实进入正式运行时：0；
- 未确认患者跨材料自动合并：0；
- 一线越权查看他人资料：0。

## 十三、范围与阶段

### V2.1.1 MVP

- 将初始化采访作为飞轮内部子流程；
- 自适应盘点和可恢复状态；
- 角色、机构、部门和本人/成员建立；
- WorkBuddy结构化配置与安全投影；
- 第一条材料真实分析；
- WorkBuddy定时任务授权、安装和回读；
- 完成页及四个日常入口。

### V2.1.1 后续增强

- Excel和名单截图的更强纠错；
- “完善我的设置”渐进补档；
- 设置健康检查和修复；
- 多部门、多主管团队；
- Claude和Trae可用时的宿主调度适配。

### 明确不做

- 不在首次设置中蒸馏完整机构知识；
- 不预装科室顾虑模板；
- 不自动读取个人微信数据库；
- 不自动发送消息或写入CRM；
- 不接入预约、到院、付款结果；
- 不用画像推断性格、收入、忠诚度或绩效；
- 不因为完成采访就宣称转化率提升。

## 十四、主要风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 八题采访过长 | 用户未看到价值就退出 | 必答不超过5轮，其余渐进补档 |
| 多文件形成双重真源 | 配置冲突、报告作用域错误 | 结构化配置唯一真源，Markdown仅投影 |
| 用户误把口述当机构事实 | 产生错误医生、价格或疗效信息 | 敏感事实独立审核，不在首次设置转正 |
| 只写自动化配置却没有真实调度 | 用户第二天没有报告 | 调度回读成功才标记开启 |
| 第一次要求过多授权 | 用户不信任产品 | 首条价值完成后再请求自动运行 |
| 第一条样本质量差 | 用户误判产品无效 | 明确材料质量，允许换一条重新验证 |
| 画像包含个人或患者隐私 | 泄露和合规风险 | 默认不保存患者原文，受控投影和单独确认 |

## 十五、实施顺序

1. 建立 V2.1.1 onboarding 数据合同和状态机；
2. 把现有初始化采访的角色模板、字段和第5题价值演示迁入飞轮；
3. 改造初始化脚本，支持机构、部门、成员和调度字段的原子写入；
4. 建立 WorkBuddy `USER.md` / `MEMORY.md` 安全投影；
5. 打通“上传第一条 → V2.1任务 → 报告 → 用户确认”；
6. 实现 WorkBuddy定时任务安装与回读；
7. 设计设置完成页和四个日常入口；
8. 用一线和主管两条路径各做至少10次可恢复回归；
9. 用1—2个真实机构完成5分钟首次设置试点。

## 十六、最终产品定义

V2.1.1完成后，以下一句话必须真实成立：

> 用户安装AI咨询转化飞轮后，只回答机构、角色和团队等最少问题，上传一条真实材料就能看到可信分析；确认有价值后授权一次自动运行，以后只需要放入截图和录音，第二天查看今日重点。

如果只是完成八题采访、生成一份画像，却没有建立工作区、完成首条分析并验证自动运行，就不能称为首次设置向导完成。
