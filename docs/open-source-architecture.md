# AI咨询转化飞轮 V2.2：开源母体架构

## 产品定义

AI咨询转化飞轮是面向医疗咨询团队的开源 Agent Skill，不是某家机构的定制项目。所有用户安装相同的公共 Core；机构资料、患者材料、审核结论和团队能力只在用户自己的工作区内生长。

```text
GitHub Public Core
        ↓ 安装或升级
Organization Workspace
        ↓ 本地蒸馏与独立审核
Organization Runtime
        ↓ 主管与一线使用
Personal Overlay
```

公共 Core 提供可复用机制，机构工作区提供真实上下文，两者通过稳定的数据契约连接。Core 升级不能携带或覆盖机构数据；机构运行时发布也不会改变 GitHub 项目版本。

## 仓库职责

仓库应包含：

- 单入口 Skill 与按需读取的参考资料；
- 通用咨询分析、每日复盘、内容行动和训练工具；
- 工作区 Schema、迁移工具和向后兼容测试；
- 隐私、医疗安全、审核和发布完整性控制；
- 完全合成的演示生成器和回归测试；
- 构建、校验和 GitHub Release 自动化。

仓库不得包含：

- 真实录音、微信截图、聊天记录和患者档案；
- 机构名称、成员名单、价格、医生、活动和内部 SOP；
- IMA 凭证、第三方密钥和真实缓存；
- 用户工作区、机构运行时和离线团队导出包。

## 维护原则

1. 业务功能先证明属于公共不变量，再进入 Core。
2. 机构差异通过本地知识与运行时表达，不通过 Fork 主代码表达。
3. `VERSION` 是 Core 版本唯一真源；工作区 Schema 独立演进。
4. 每次发布必须通过完整测试、隐私扫描、确定性构建和产物复核。
5. 破坏性 Schema 变化必须提供预览、迁移和回滚说明。
6. 默认零遥测；真实材料永不作为公开 Issue 的复现附件。

## 默认用户路径

```text
安装同一份公共 Core
→ 不超过 5 轮初始化采访
→ 在业务目录建立私有工作区
→ 用第一条真实材料验证
→ 日常全量分析与重点呈现
→ 本地审核和能力成长
→ 更新 Core 时保留全部本地数据
```

离线团队运行包只服务于不能共享同一工作区的设备分发，不是普通用户必须理解或执行的步骤。
